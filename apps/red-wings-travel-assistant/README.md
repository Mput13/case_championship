# Red Wings Travel Assistant

Локальный веб-прототип: Node.js ESM >=22.19.0, Pi agent-core/ai 1.5.2 и DeepSeek через API МАИ. Публикация исключена из текущего объёма по выбору пользователя 13.11.2026. Сервер строит варианты из датированных расписаний Red Wings; наземная дорога остаётся рекомендацией с навигационной ссылкой. UI находится в `public/` и разрабатывается отдельно.

## Запуск

Из каталога `apps/red-wings-travel-assistant/`:

```sh
npm ci --ignore-scripts
npm start
```

Адрес по умолчанию: `http://127.0.0.1:3080`. Порт и интерфейс задаются через `PORT` и `HOST`. Сервер отдаёт `public/index.html`, если UI уже добавлен, и три API-метода независимо от наличия UI. Для первого запуска нужны зависимости из package-lock.json.

Файл `.env` автоматически не читается. Для настройки можно скопировать `.env.example` в `.env` и запустить:

```sh
node --env-file=.env server.mjs
```

Секреты заполняет координатор. Не помещать ключи, `.env` или файл ключа в `public/`. За обратным прокси требуется точный `PUBLIC_ORIGIN`, например `https://example.org`, для браузерных POST. По умолчанию браузерные POST принимаются только с того же локального origin; CORS не включён. Прототип не содержит пользовательской аутентификации и не предназначен для открытого доступа с включённым платным LLM.

```sh
npm test
```

Проверено 13.11.2026 на Node v26.13.1: 31 offline-тест, включая HTTP на временных loopback-портах. Это offline-проверки. Отдельно координатор проверил настоящий HTTP -> план -> Pi -> DeepSeek на сохранённом расписании; live-Яндекс, browser E2E и Docker не проверены. Тесты не обращаются к внешним API и не используют реальные ключи.

## API

- `GET /api/health`: `status`, `model_configured`, `schedule_mode`, `generation_enabled`, `schedule_configured`, при полной конфигурации — `model`. Health не выполняет сетевые запросы и не доказывает работоспособность провайдера. `model_configured` обозначает наличие настроек, а не проверку токена или модели.
- `GET /api/examples`: `examples:[{id,label,request}]`, `cities`, `dates`, `max_date_days`, `coverage_note`, `data_mode:"snapshot"`. Примеры относятся к сохранённому покрытию; это не обещание live-наличия.
- `POST /api/plan`: JSON по контракту brief. Поддержаны `trip` и `flight`; в режиме `flight` обязательны `flight_number` и `flight_date` внутри выбранного периода. `ИН 1034` и `WZ 1034` нормализуются к `WZ 1034` только при проверенной принадлежности перевозчику. `origin`/`destination` — названия поддержанных городов или их IATA-коды. В этом прототипе они обозначают города выбранного рейса; отдельные города наземного подъезда вне покрытия не маршрутизируются.

```json
{
  "mode": "trip",
  "origin": "Самара",
  "destination": "Екатеринбург",
  "date_from": "2026-12-08",
  "date_to": "2026-12-08",
  "preference": "balanced"
}
```

Дополнительные поля `origin_address` и `destination_address` уточняют навигационные ссылки внутри выбранных городов (до 240 символов). Непустой `message` отклоняется как неподдержанный: свободные пожелания нельзя молча игнорировать. Варианты определяются структурированными полями формы. Произвольные сообщения и адреса не передаются LLM и не логируются.

| Статус | Значение |
| --- | --- |
| `ok` | Есть подтверждённые прямые рейсы; при частичном покрытии ответ явно перечисляет непроверенные даты. |
| `no_routes` | Полностью проверенный ответ в выбранном покрытии не содержит подходящего прямого рейса. Это не утверждение об отсутствии всех способов поездки. |
| `needs_data` | Город/дата вне покрытия, отсутствует live-ключ либо сохранённая страница неполна и подходящий рейс не найден. |
| `error` | Ошибка коннектора или запроса. Live не заменяется снимком. |

Доменные результаты возвращаются с HTTP 200; сбой коннектора — 502, некорректный запрос — 400/413/415, превышение лимита — 429. Во всех случаях используются поля `status`, `data_mode`, `variants`, `sources` и понятное сообщение. Независимые ошибки агента отражаются в `assistant.status`, сохраняя варианты расписания.

У варианта три участка: наземная рекомендация, подтверждённый рейс, наземная рекомендация. Время наземных участков и все цены — `null`. Поэтому общие `departure`, `arrival`, `duration_minutes`, `total_price` тоже `null`; даты рейса находятся в `legs[]`. Дополнительное поле `duration_minutes` у авиаучастка считается только по двум подтверждённым timestamp с часовыми поясами.

Все варианты содержат Red Wings с кодом Яндекса `617` **и** IATA `WZ`. Рейсы других перевозчиков и строки, идентифицированные только по названию/номеру, не превращаются в варианты. Пересадки не строятся. `balanced` и `fewest_changes` возвращают прямые вылеты по времени отправления; для `fastest` явно указано, что общей длительности для ранжирования нет. Максимум 3 варианта; усечение отражается в сообщении.

## Снимок расписаний

`data/snapshot.json`: 20 российских аэропортов, 43 датированных рейса на **8 и 11 декабря 2026 года**. Это локальный снимок, не live-данные и не наличие мест. Данные других дат не интерполируются.

Источник вылетов — `context/40_swarm_pricing_research_20261113/yandex_hub_schedules.json`. Для трёх рейсов время прилёта взято из `yandex_spotlight_search.json` после точного сопоставления кода перевозчика, номера, времени вылета и обеих станций:

| Дата | Рейс | Маршрут | Вылет | Прилёт | Время авиаучастка |
| --- | --- | --- | --- | --- | --- |
| 08.12.2026 | WZ 1034 | Самара → Екатеринбург | 08:00 +04:00 | 10:40 +05:00 | 100 мин |
| 08.12.2026 | WZ 1068 | Казань → Екатеринбург | 07:25 +03:00 | 11:00 +05:00 | 95 мин |
| 08.12.2026 | WZ 1025 | Екатеринбург → Уфа | 22:30 +05:00 | 23:45 +05:00 | 75 мин |

В остальных 40 строках прилёт остаётся `null`. У расписания Пулково сохранено не более 200 результатов; полная выдача больше. Отрицательный результат на такой странице означает `needs_data`, а не отсутствие рейса.

Для каждого рейса сохранены ключ исходного ответа и JSON pointer, для исходных файлов — SHA-256. `fetched_at` и ответный `checked_at` равны `null`: точного времени HTTP-получения источники не содержат. `file_modified_at` фиксирует время локального файла, `extracted_at` — время извлечения; они не выдаются за сетевую проверку. Исходные файлы нужны только для повторного извлечения и теста provenance, запуск приложения автономен.

```sh
npm run snapshot
```

Экстрактор читает только два фиксированных файла, ничего не скачивает и не меняет источники. Снимок формируется детерминированно по содержимому, кроме времени извлечения и метаданных файла. Тест проверяет SHA и ссылки на исходные строки; при изменении источников старый снимок не считается автоматически проверенным.

## Live-коннектор Яндекса

Включается только `SCHEDULE_MODE=live` и отдельным `YANDEX_RASP_API_KEY`. По умолчанию — `https://api.rasp.yandex-net.ru/v3.0/search/`; поддержан также официальный прежний хост `api.rasp.yandex.net`. Базовый путь можно настроить через `YANDEX_RASP_BASE_URL`, но другой хост будет отклонён.

Используется [документированный поиск между станциями](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point): коды аэропортов, дата, `transport_types=plane`, `transfers=false`, `limit=100`; авторизация в заголовке, без ключа в URL. Документация прочитана 13.11.2026; реальный запрос с ключом **не выполнялся**.

На каждый день выполняется один запрос без повторов, максимум 7 дней; неполная пагинация отмечается как неполное покрытие. До двух одновременных live-поисков, внутри одного дни проверяются последовательно. Даты live ограничены текущей UTC-датой и следующими 365 днями; границы предоставляемого Яндексом расписания этим не гарантируются. Не распознанные или противоречивые поля не подменяются расписанием из памяти. Цены и остатки мест не запрашиваются.

## Pi и МАИ

Точный ID `deepseek-v4.1-flash` получен из авторизованного `/v1/models`; `/v1/chat/completions` проверен. Выбран `AGENT_ENGINE=pi`; исходный `direct` оставлен для сравнения.

Генерация выключена по умолчанию. В `.env.example` указаны проверенные модель и протокол. Нужны `ENABLE_LLM=true`, `MAI_API_KEY_FILE` с путём к защищённому файлу вне проекта либо серверный `MAI_API_KEY`. В рабочем запуске координатора ключ читается из защищённого файла T3 и не копируется в репозиторий.

`MAI_CA_FILE=./certs/russian-trusted-root.pem` задаёт официальный публичный root для выделенного HTTPS-клиента. Проверяется SHA-256 DER `d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`; доверие действует только на фиксированный endpoint МАИ с проверкой имени. Системное доверие и `NODE_TLS_REJECT_UNAUTHORIZED` не изменяются.

Pi объясняет рассчитанный кодом план: `get_trip_facts` читает факты; `compose_summary` выбирает 1–2 полезных пояснения. В UI попадает только текст серверных фактов. Модель не генерирует расписание, цены, URL или команды; адреса и свободный текст ей не передаются. Это ограниченный агент пояснений, а не свободный диалоговый планировщик.

До двух модельных вызовов на запрос, максимум 512 output tokens на каждый, ноль автоматических повторов. Неизвестный usage останавливает продолжение. `MAX_LLM_CALLS=20` ограничивает вызовы за время жизни процесса; это технический предел локального пилота, не денежный бюджет и не суточная квота. Тариф МАИ неизвестен: `cost_status=unknown`. Нули в обязательных pricing-полях Pi — внутренние заглушки; стоимость МАИ из них не выводится.

Нормальное окончание настоящего цикла Pi и локального HTTP API подтверждено в `context/43_travel_assistant_20261113/receipts/mai_pi_tool_smoke.json` и `app_pi_smoke.json`. Это работа на сохранённом расписании, не live-мультимодальность, наличие мест или продажа. При недоступности LLM варианты расписания сохраняются.

## Ограничения исполнения

JSON body — до 8192 байт, города — до 100 символов, диапазон — 1–7 календарных дней включительно. Принимаются только существующие ISO-даты, времена источника требуют часового пояса. Не более четырёх одновременных POST, 30 POST в минуту на процесс, одного агентного запуска одновременно. Лимиты повторно не запускают отвергнутые запросы.

Timeout внешнего HTTP по умолчанию 10 с (максимум 15 с), LLM 20 с (максимум 30 с); общий abort плана — 45 с. Ответ расписания ограничен 1 MiB, Pi-транспорт — 256 KiB. Исходящие хосты и внешние ссылки проверяются по точному allowlist; редиректы с авторизацией запрещены. Ссылки генерирует код для `rasp.yandex.ru`, `flyredwings.com` и `yandex.ru/maps`, исходные/модельные URL не исполняются.

Запросы, адреса, сообщения, ответы провайдеров, ключи и stack trace не логируются. Статические файлы доступны только внутри `public/`, включая проверку symlink; `.env` и серверные исходники не раздаются. Данные запроса не сохраняются в базу или на диск.

Dockerfile подготовлен для Node 24 и npm ci; сборка и запуск Docker не выполнялись. Для сборки нужен готовый `public/` от UI-агента. Секреты передаются при запуске, не копируются в образ. Публикации и перезапуски существующих сервисов не выполнялись.

## Файлы ядра

- `server.mjs` — HTTP API и раздача UI.
- `src/validation.mjs` — входной контракт, даты, часовые пояса и номера рейсов.
- `src/planner.mjs` — варианты, наземные рекомендации, примеры и статусы.
- `src/schedules.mjs` — snapshot/live адаптеры, проверка перевозчика и покрытия.
- `src/network.mjs` — allowlist, timeout, размеры ответов, concurrency и отсутствие retries.
- `src/links.mjs` — генерация внешних ссылок.
- `src/pi-agent.mjs`, `src/mai-transport.mjs` — ограниченный Pi-цикл и host-scoped TLS.
- `certs/russian-trusted-root.pem` — публичный root, не секрет.
- `src/agent.mjs` — порт агента и отключённый по умолчанию MAI-адаптер.
- `src/config.mjs` — настройки и пределы.
- `src/build-snapshot.mjs` — воспроизводимое извлечение из source receipts.
- `data/snapshot.json` — компактное расписание и provenance.
- `tests/core.test.mjs`, `tests/adapters.test.mjs`, `tests/server.test.mjs` — offline-проверки.
- `package.json`, `.gitignore`, `.env.example`, `Dockerfile`, `README.md` — запуск и конфигурация.

UI в `public/` интегрирован координатором. Адреса меняют навигационные ссылки; расчёт даты наземной дороги не выполняется. Свободный чат, багаж, бюджет, покупка, PNR и защита стыковки не поддержаны. Публикация исключена по выбору пользователя; браузерный E2E остаётся отдельной проверкой. Проверка raw provenance в npm test требует двух исходных локальных capture-файлов; они не являются npm-зависимостями.
