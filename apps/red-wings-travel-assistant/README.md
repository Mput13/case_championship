# Red Wings Travel Assistant

Прототип планировщика поездки: Node.js ESM, Pi agent-core/ai 1.5.2 и `deepseek-v4.1-flash` через API МАИ. Интерфейс рассчитан прежде всего на телефон. Временная демонстрация: https://redwings.altair.ad/agent/ (13.11.2026, до 19:51 МСК).

Пользователь выбирает точки А/B из подсказок, дату или гибкое окно выезда, при необходимости — рейс Red Wings и пожелания. Найденные варианты и параметры сохраняются в сессии; обсуждение продолжается в чате. Требования: [MULTIMODAL_SPEC](../../context/43_travel_assistant_20261113/MULTIMODAL_SPEC.md) и [контракт](../../context/44_travel_assistant_chat_20261113/contract.md).

## Запуск

Нужен Node.js >=22.19.0. Из этого каталога:

```sh
npm ci --ignore-scripts
cp .env.example .env
node --env-file=.env server.mjs
```

`.env` автоматически не читается. Для нового интерфейса задать `ENABLE_CHAT=true` и `PUBLIC_DIRECTORY=./public-chat`. Локальный адрес по умолчанию — `http://127.0.0.1:3080`.

Ключ Расписаний задаётся через `YANDEX_RASP_API_KEY_FILE`, ключ МАИ — через `MAI_API_KEY_FILE`: это пути к защищённым файлам вне репозитория. Допустимы и серверные переменные `YANDEX_RASP_API_KEY` / `MAI_API_KEY`. Для живого чата нужны `ENABLE_LLM=true`, модель и протокол из `.env.example`. Ключи не передаются в браузер и не входят в URL запросов к Расписаниям.

Лимит ответа по просьбе пользователя увеличен до 4096 токенов (`MAX_OUTPUT_TOKENS`, допустимо 512–8192). Время одного модельного вызова — до 120 секунд, всего хода — до 180 секунд; таймаут HTTP и прокси — 240 секунд. Сохранены максимум три модельных вызова на ход, запрет автоматического повтора POST и остановка при неизвестном расходе. Публичный интерфейс обращается к `/api-v2/`; сервер поддерживает также прежний `/api/`.

`MAI_CA_FILE=./certs/russian-trusted-root.pem` включает отдельный доверенный корень только для клиента `api-ai.mai.ru`; имя хоста и отпечаток сертификата проверяются. Системное доверие и проверка TLS не отключаются.

## Интерфейс и API

- `GET /api/places?q=...` — локальные подсказки российских городов, станций и аэропортов из справочника Яндекса. Подсказки домов не подключены; необязательный адрес остаётся отдельным полем.
- `GET /api/flights?from=...&date=...` — датированное табло Red Wings. Выбор получает серверный ID с ограниченным сроком действия. Неизвестное время прилёта не выдумывается.
- `POST /api/chat/start` — `origin_id`, `destination_id`, `date_from`, необязательные `date_to`, `flight_option_id`, `origin_address`, `destination_address`, `wishes`. Без пожеланий первичный поиск работает без LLM; пожелания сначала поступают Pi и учитываются до подбора.
- `POST /api/chat` — `{session_id?,message}`. История, Trip и результаты хранятся сервером. Клиент не передаёт историю, инструменты или URL для загрузки.
- `GET /api/demos` и `POST /api/chat/demo` с `{id}` — четыре заранее проверенных примера разных типов. Снимок и сценарий явно подписаны; открытие не вызывает модель или транспортные API. Продолжение использует ту же сессию.
- `GET /api/health` — состояние конфигурации; проверка токена или внешних сервисов этим запросом не выполняется.

`reply_origin` различает `planner`, `prepared` и ответ модели. Сохранённый пример не представляется свежим поиском. Старые `public/` и `/api/plan` сохранены как предшествующая версия; при подключённом чате старый POST закрыт.

Обычный интерфейс после первичного поиска без пожеланий запрашивает разбор агента в той же сессии. Открытие примера онлайн также вызывает настоящий Pi/DeepSeek по сохранённым фактам. Кнопка «Офлайн-демо» открывает четыре локальных снимка без API-вызовов; чат и новый поиск в этом режиме выключены. После включения агента выбранный снимок передаётся в серверную сессию при первом вопросе. Снимки собираются командой `node scripts/build-offline-demos.mjs`; перед записью проверяется каталог и временные буферы. Для работы после потери сети страница и JSON должны успеть загрузиться; установка PWA и холодный запуск без сети не реализованы.

## Источники и проверка маршрутов

Яндекс Расписания: `stations_list`, `nearest_stations`, `schedule`, прямой `search` и `search` с `transfers=true`. Реальные `train`, `suburban`, `bus`, `plane` сохраняют номера, станции, локальные смещения UTC и ссылки. Составные ответы показывают отдельные перевозки. Цена и места остаются неизвестными, если источник их не подтвердил.

Справочник покрывает около 8 тысяч российских населённых пунктов и 33 тысяч станций. Открытый каталог OurAirports используется для отбора географических кандидатов аэропортов; он не подтверждает действующий рейс или статус работы аэропорта. Промежуточный индекс хранится в игнорируемом `.runtime/`.

Общий поиск рассматривает до пяти аэропортов в радиусе 450 км, одно авиаплечо и наземные цепочки. До 24 транспортных запросов на подбор, включая до двух составных наземных поисков. Для длинного окна выбираются перспективные даты; все дни и все маршруты не перебираются. Выбранный рейс проверяется на свою дату. Авиаперелёты — исключительно Red Wings; для сравнения допустим только наземный путь. Рабочий предел подвоза к перелёту — восемь часов на каждую сторону; это настройка прототипа, а не правило перевозчика. Если разумная цепочка WZ не подтверждена, предлагаются другие даты, аэропорты либо наземный путь.

Код исключает невозможную последовательность времени и стыковки с недостаточным запасом: минимум 120 минут перед самолётом и 60 после прилёта, плюс физический переезд. Неизвестный переход оставляет `partial`. Ожидания более пяти часов и ночёвки видны и снижают ранг. Буферы не являются гарантией при задержках.

Для коротких переходов между публичными станциями локально доступен `ENABLE_OSM_WALK_ROUTING=true`: Valhalla / OpenStreetMap, кеш и максимум один запрос в секунду. Пользовательские адреса туда не отправляются. Это оценка пешего перехода, а не датированная перевозка. У публичного сервера есть [правила использования](https://github.com/valhalla/valhalla#demo-server); для публичной эксплуатации требуется отдельное решение о маршрутизаторе.

## Партнёрские сервисы и сценарии

Подтверждённый сервис Red Wings / партнёра получает приоритет при сопоставимом времени и удобстве. Исходная настройка сопоставимости — до 15 минут общего пути без дополнительных пересадок или ночёвки. Неизвестные показатели и статус концепта исключают такую рекомендацию. Общественные альтернативы остаются видимыми.

«Умный трансфер» и единая корзина White Label РЖД-ЦПР пока целевые интеграции. Оплата, наличие мест, страхование, ваучеры, сбои и базовый авиачекаут не реализуются. Сценарная сеть 2027–2028 отделена от действующих расписаний. OMS → IKT, 3 RT/нед — условие демонстрации, не опубликованный рейс.

## Проверки и эксплуатация

```sh
npm test
```

Offline-тесты не используют реальные ключи и не обращаются к провайдерам. Реальные транспортные проверки, HTTP-ответы и проверки интерфейса сохраняются в [context/44](../../context/44_travel_assistant_chat_20261113/). Первое настоящее HTTP → Pi → МАИ общение с уточнением дат также сохранено там. Проверка конфигурации, offline-тесты, живой поиск, ответы модели и визуальная приёмка — разные уровни подтверждения.

Сессии находятся в памяти и истекают по TTL. Данные пользователя не записываются в базу или серверный журнал. На модельный ход действует предел трёх вызовов; неизвестный usage останавливает продолжение. Автоматического повтора модельного POST нет. `MAX_LLM_CALLS` — технический предел процесса, не денежный бюджет; тариф МАИ не подтверждён.

На демонстрационном сервере опубликован HTTPS-адрес `/agent/`: Node.js 22.23.5, отдельный системный пользователь и systemd-сервисы за nginx. Файлы дашборда сохранены побайтно; кнопка добавляется nginx только в HTML-ответах трёх входных страниц. Ключи находятся вне веб-каталога и удаляются таймером в 19:51 МСК 13.11.2026; одновременно останавливаются обе версии агента. Подробности и проверки: [deployment.md](../../context/44_travel_assistant_chat_20261113/deployment.md). Dockerfile подготовлен; Docker-сборка не запускалась.
