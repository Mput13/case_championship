# Исправление привязки независимого oracle

Статус: **проверено координатором; независимый recheck ожидается**. Исходный MR14 сохраняет `CHANGES`. Это исправление происхождения проверочных данных, а не новый экономический расчёт.

В guard из `7e65c687e12cf45534852a3c47d6a5c8cf7dda07` список файлов и хешей oracle читался из изменяемого receipt. Подмена receipt могла пройти проверку и сохранить в выходе ссылку на MR11. В фактически сохранённом пакете oracle верный: координатор отдельно сравнил три файла с exact MR11 `ea2a9626aef75c121f2da7d778b47edce0d571b7`.

Отдельный `admit_frozen_interaction.corrected.py` добавляет проверку SHA256 байтов receipt **до его разбора**. Ожидание `8373a8085682cc9df3660433f8024a78a377f9b512c93d05ecaafbc9a71d2db6` закрепляет commit, пути, охват и хеши трёх oracle-файлов. Следом выполняются прежние проверки их содержимого. Минимальная правка предложена независимым MR14 `f579eeb888a98554b901afeee628c30a85cc48bf`; координатор применил её только к этой производной копии.

Воспроизведение:

```sh
python3 -B context/23_night_run_20261110/input_admission_correction/verify_correction.py
```

Скрипт извлекает из Git только необходимые закреплённые код и входы в временный каталог внутри своего scope. Запускает исходный и исправленный `main`, сохраняет результаты проверки, удаляет временный runtime. Для запуска нужны доступные Git objects исходных SHA; сеть и зависимости не нужны. Отдельный corrected-файл предназначен для проверки и адресного переноса владельцем, а не для запуска в текущей папке без его входов.

Лично проверено координатором:

- 16 входных Git blobs; receipt и все три oracle-файла совпадают с закреплёнными источниками. Grain: 384 уникальных itinerary, 12 групп, 160 затронутых поездок; пример с одним сквозным тарифом сохранён в `validation.json`.
- Три выходных файла baseline побайтно равны исходным опубликованным результатам. Все семь прежних отрицательных проб сохраняются.
- Четыре обхода привязки receipt воспроизведены в исходном `main` и отвергнуты в исправленном. Ещё семь порч oracle/support/основных входов отвергнуты обоими вариантами. Полные before/after — `validation.json`.
- Разница кода — только закрепление receipt. Старый interaction-код, формулы и все frozen-расчёты не менялись; этот новый guard не подключён к старому коду автоматически.

Исправление относится только к exact-input guard. Новые данные требуют нового input set, oracle и проверки. Оно не подтверждает наблюдённый рынок, фактический парк, полный бюджет или запуск. Ранее принятые scoped MR11/MR12/MR13 результаты сохраняют свою область; исходный P2 и текущая независимая приёмка исправления записываются отдельными событиями.
