# Общие ограничения и сценарий отмены

Пакет `methods-integration-v5` соединяет исправленную временную проекцию MR02 с точными вариантами context21. Новые расчёты ниже — **AGENT_PROPOSAL, independent review pending**. MR08@7a868d12 завершил scoped APPROVE на exactabb1, MR09 проверяет exactc24; их приёмка не переносится на v5.

## Отмена зависит от версии продаж

Фиксированы рейсы H_UFA_4/H_UFA_8, цены/расходы Цири и синтетический эпизод UFA **7 декабря 00:00 — 8 декабря 00:00 UTC**, с исключённым правым концом. Из всего множества itinerary один раз отбираются поездки, использующие хотя бы одно отменённое плечо. Сквозная выручка не умножается на число затронутых плеч.

Политика `cancel_pretravel_no_protection` предполагает отмену до начала поездки, без защиты/перебронирования. Сохраняются исходные потери старых продаж RW; их восстановление не выдумывается. Экономятся только несожжённый топливный продукт и неоказанные новые пассажирские услуги. Возврат билета не становится вторым расходом сверх потери признанной выручки. Неизвестные компенсации, договорные штрафы и обслуживание остаются вне численной добавки, не объявляются бесплатными.

В качестве входов отдельно взяты C и N из immutable common-v3. C — сценарные bands, N — годовой proxy Анастасии, делённый на104. N не является наблюдённым зимним конечным OD. Спрос и цены после отмены не переоптимизируются.

| Программа, base | Добавка отмены при C, RUB | Добавка при N, RUB | Ошибка при переносе C-добавки в N |
|---|---:|---:|---:|
| H_UFA_4 | +255 219.47 | −605 120.27 | +860 339.74 |
| H_UFA_8 | +854 454.45 | −998 495.53 | +1 852 949.98 |

Оба знака меняются. Более высокий сценарный объём продаж увеличивает потерю выручки отменённой волны при тех же топливных расходах. Это не выбор правильного спроса и не рекомендация ограничений: программы перевозят разное число поездок, полный бюджет неизвестен, а все сравниваемые конечные вклады остаются отрицательными.

Для альтернативного договора `cancel_usage_billed_sensitivity`, где дополнительно устранимы заправка, часовой резерв ТО и навигация, base-добавки N равны +132 011.47 / +348 517.27 RUB для UFA4/UFA8. Такие права на экономию не наблюдены. Их нельзя получить от одной смены названия статьи «переменная».

В cautious отмена также меняется с рецептом: например, UFA8 по первой политике даёт +8 740 651.34 при C и +7 024 939.04 при N до дополнительных затрат. Положительная разность здесь означает уменьшение убытка невыполненной программы; она не описывает пользу сбоев для пассажиров или компании в полном горизонте.

**Практическое правило адаптера:** денежный overlay соединяется по input_set, variant, profile, source_commit, программе, сценарию и точному множеству itinerary. Нельзя механически прибавлять δ(C) к новому N-результату или к mixed-портфелю. В `runs/kover_demand_v1/` каждый рецепт получил собственный event join и пересчёт потери выручки/пассажирских расходов; `runs/kover_accounting_v1/` отдельно хранит только исходный C-контур.

## Предел ещё не учтённых расходов

Для C/base дополнительная нагрузка на одну не обслуженную конечную поездку, полностью поглощающая положительную начисленную добавку отмены, равна:

- H_UFA_4: **750.03 RUB/journey** при 340.278 модельных поездках;
- H_UFA_8: **1381.73 RUB/journey** при 618.394 модельных поездках.

Это обратные арифметические пороги, не действующая компенсация, не цена защиты и не эмпирический диапазон. Затраты могут возникать по клиенту, ночи, событию или рейсу — их нужно сначала привести к правильному объёму и не начислить дважды.

Относительное преимущество H_UFA_4 перед D_previous_best8 в C/base после такой отмены равно655385.75 RUB до базы и прочих различий. Оно исчезает при дополнительной нагрузке **1926.03 RUB на затронутую поездку**, если B и ΔO равны0 именно как условие этого порога. В общем виде граница: `655385.75 − θ·340.278 − B − ΔO = 0`; неизвестные B/ΔO нулём не заполняются. Авторские5000 RUB/journey можно подставить только как явно названный стресс: тогда разность становится −1 046 004.76 RUB до B/ΔO. Это не правовая норма или счёт RW.

Транспортный результат не одинаков: отмена оставляет поездки без обслуживания. Денежное ранжирование с меньшим объёмом услуги не выбирает финальную сеть кейса. H_UFA_4 остаётся четырёхлучевым этапом, а не выполнением требования8–12.

## Cash и перенос волны

Для C/UFA8/base отмена даёт +854454.45 RUB в начисленном результате, но в заданной MR02 net-cash последовательности требует **6 078 104.30 RUB** дополнительного покрытия относительно того же baseline до следующего пополнения топлива. Для UFA4 аналогичная потребность —3 519 154.69 RUB. Здесь заданы порядок платежей и предоплата net fare100%, а действительный gross/VAT неизвестен; полный фактический cash peak остаётся NULL. Пересчёт баланса «результат − запасы + обязательства» и итогов выполнен по восьми отдельным журналам событий.

Проекция координатора `87ee52de15c2bdf396d9c06ba600fd413d5ab4a8` исправляет epoch отдельно от originalafadee. Её уровень — **PARENT_TIMEBASE_AND_DELTA_CHECK_ONLY**, independent correction recheck **NOT_RUN**. Четыре hub-delay строки имеют HOLD и NULL для обслуженных/необслуженных количеств и доступного денежного результата. Исходная арифметика хранится только как `hypothetical_if_recovered`. Для D_SVX8 нельзя копировать MR02 D_pilot: это разные программы. Нулевой эффект данного UFA-эпизода доказан по 16 собственным модельным рейсам D_SVX8, у которых UFA не является конечным аэропортом. ## Общий D и частотный закон в смешанной программе

`runs/portfolio_v2/` добавляет к v4 отдельную ветвь **D_GUARD_STANDALONE_CLAIMS**: исходные желаемые доли каждой компоненты сохраняются, но продажи всех её конкурирующих предложений расходуют один направленный D после проверки физических кресел. Это обязательный общий лимит; Q(F) остаётся другим сценарным выбором.

Во всех **30 сочетаниях набора/сценария** D-only не меняет сумму standalone-вкладов. Синтетический контрпример подтверждает, что guard действительно действует: четыре доступных предложения без общего лимита дают400 при D300; с ним продажи300. Это не новый дефект фактических30 сочетаний.

Для D_SVX8 + D_previous_best8 base три состояния теперь записаны явно:

| Учёт общего рынка | Вклад, RUB/неделю |
|---|---:|
| Сумма standalone | −12 349 501.43 |
| Один D, прежние claims | −12 349 501.43 |
| Общий сценарный Q(F) | −12 795 565.32 |

Снижение446063.89 вызвано предложенным законом захвата, а не текущим превышением всего рынка. Все60 старых portfolio-v1 численных результатов сохранены; новый набор содержит90 строк по трём законам. Реакция на частоту, расписание/качество альтернатив и фактический OD по-прежнему не подтверждены.

При дополнительной проверке воспроизводимости найдено только неустойчивое расположение строк календаря из-за обхода множества бортов. Новый replay сортирует идентификаторы. Исходные v1 bytes сохранены; `runs/portfolio_v1_replay/replay_equivalence.json` подтверждает равенство всех значений. Это техническая детерминизация, без изменения финансовых или календарных выводов. Старые v1 каталоги больше не являются местом записи нового portfolio replay.
