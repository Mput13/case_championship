# Решения координатора для единственного адресного раунда интеграции

Это предложения для проверки команды, а не утверждённые веса/стратегия. Финансовые расчёты хаба не выполняются.

1. Применить рекомендованные 100-балльные веса и четыре альтернативы методического агента вместе с правилами UNKNOWN/фиксированных шкал. Фильтр500км оставить основным. Не менять скрыто набор опорных координат: основной исторический набор и ZIA+SVX-сценарий различать.
2. Статус Самары как опорного аэропорта подтверждён основной моделью по сообщениюRW27.10.2026. Основной режим допускает развитие опоры; строго-новый сценарий исключает все подтверждённые опоры симметрично. Текущий физический статус других узлов не выводить из отсутствия строки или Википедии.
3. Первично подтверждённое опубликованное ТОSSJ вOMS на03.12.2024 учитывать как возможность обслуживания, сохранив неизвестными текущие договор/свободную мощность/всю область допуска. Категорическое отрицание базы/опорыOMS и вывод о росте балла от ухудшения competitor_hub не приняты.
4. REN: первичный факт за2025 — `>951000`; точный итогUNKNOWN. Есть первичные округлённые компоненты885500+65600. Показывать консервативный lower-bound сценарий и сценарий стандартного округления (см.main_source_checks.md); не поднимать центральную оценку к миллионам из-за формального верхнего якоря12,5млн без реалистичного обоснования. Отличие от первоначального общего правила midpoint(lower,1) явно назвать адресным уточнением по найденной информации о точности публикации. Не создавать фиктивный точный итог951100.
5. KUF/REN transfer_zone и ssj_mro остаютсяUNKNOWN; .5 — только импутация, не факт. Слабые исходные competitor_hub=.25/.75 и косвенноеТО=.5 не должны обходить диапазоны неопределённости.
6. Исправить и продемонстрировать погодный sentinel/валидный знаменатель; при отсутствии нужных raw/покрытия не объявлять погодный показатель подтверждённым. Проверить введения-only«Ковра» как диагностику, не молча менять основной показатель. Пересадочные миллионы — модельныйproxy, не продажи; дополнительного широкого исследования/моделирования не делать.
7. Сырой OMS_evidence.csv структурно повреждён, не читать позиционно. Интегратор создаёт нормализованный accepted_research.csv с проверенными строками, отдельными статусом/периодом/ограничениями; старые отчёты сохраняются как история с явно исправленными выводами.
8. Последний этап — независимая приёмка интеграции. После неё третьих раундов/новых поисков не будет: нерешённое фиксируется, результат выпускается с ограничениями.
