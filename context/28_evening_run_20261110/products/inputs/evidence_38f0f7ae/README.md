## Таблицы и использование

- `pair_registry.csv`: все затронутые пары, отдельные счётчики свидетельств и пробелы. 45пар включают физические плечи, OD пересадок, дополнительные зарегистрированные варианты C35 и исторический OMS12 и DME/SVO; это не выбранная сеть45маршрутов. MOW сохранён как неразрешённый городской агрегат, аэропорт требуется.
- `pair_hypothesis_join.csv`: `hypothesis/network/route/origin/destination/role`. КомпактныйC04 и авторский OMS12 — разные сети. Только C01 endpoint-OD и явно добавленные C07/C35 — отдельные пассажирские пары; физические плечи нельзя суммировать как независимый спрос.
- `service_observations.csv`: датированные старые записи и новые правила расписания, типы, источник/локатор/хеш. Число строк не частота. Противоположные направления и дубли разных аэропортов не складывать. Все кресла по конкретному рейсу и остатки остаются UNKNOWN без конфигурации и инвентаря.
- `subsidy_route_matches.csv`: точные строки официальной HTML-таблицы2026, с периодом, типом, креслами, частотой, парными рейсами, софинансированием. Сохраняются дробные числа исходника; пересекающиеся периоды и несколько строк не дают права сложить выплаты.
- `subsidy_controls.csv`, `subsidy_applicability.csv`, `subsidy_cap_84_103_seats.csv`, `subsidy_special_fare_grid.csv`, `subsidy_cap_examples.csv`: нормативная единица, ограничения, запись по каждой паре и верхние пределы. Примеры — диагностические границы при100креслах и коэффициенте1, не доход RW.
- `fleet_facts.csv`, `fleet_delivery_gates.csv`: типы/состояния/планы и четыре обязательные ветви. 5/10SJ-100 из docs20 остаются авторскими сценариями без подтверждённого количестваRW; новые численные обещания не добавлены.
- `source_registry.csv`, `input_manifest.json`, `raw/`, `extracts/`: первичные raw, результаты доступа, закреплённые blobs, текст и SHA256.

Сборка offline. HTTP-сбор отдельно: `fetch_sources.py web_targets*.json` (каждый файл отдельно); он меняет дату/bytes только при сознательном новом сборе. Для повторения таблиц сеть не нужна. Используются stdlib+lxml+pandas/openpyxl для чтения XLSX; для захвата PDF — установленный `pdftotext`.

`findings.md` — выводы и тезисы для паспорта, `hypothesis_readout.csv` — итог по каждому ID, `decision_gaps.csv` — точные незакрытые поля. `dated_service_instances.csv`/`weekly_service_context.csv` содержат215уникальных опубликованных отправлений выбранной недели;12сохранившихся расхождений источников не усреднены. `alternative_paths.csv` и `alternative_timing_examples.csv` дают16путей и6хронологических примеров. `fare_observations.csv` сохраняет13рекламных минимумов перевозчика с неустановленным годом/багажом, не конечные котировки. `subsidy_source_checks.json` подтверждает совпадение423строк HTML и XLSX после явно описанной нормализации.

`native_reader_diagnostic.json` фиксирует узкую read-only диагностику нативного web-reader по сообщению root: TimeoutError/(400) Timeout fetching при наличии сохранённых directHTTP200 PDF; точная внутренняя причина нативного fetch неизвестна. Дополнительный probe не понадобился, инфраструктура не менялась.

`join_checks.json` проверяет покрытие10ID и ссылки пар; PASS не является рыночной приёмкой. Неполный список перевозчиков нигде не означает нулевую конкуренцию. Будущая поддержка, свободный парк, окончательный тариф с20кг багажа, наземные альтернативы по датам и остатки кресел требуют отдельных полей; текущие UNKNOWN не превращены в нули.

## Доступ и пределы

Сессии, сервисы и профили не менялись. Browser use не требовался.
