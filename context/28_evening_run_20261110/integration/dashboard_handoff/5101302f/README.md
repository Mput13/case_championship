# Данные для дашборда и паспорта

Пакет передаёт десять рассчитанных гипотез, контекст маршрутов и варианты сети в существующий дашборд Насти/kiruha355. UI, авторские модели и публичный Site не менялись. Источники читаются только из указанных Git commits. Самостоятельная проверка сборки проверяет сериализацию; независимый review этой сборки ещё не выполнен.

## Что подключить

| Место существующего дашборда | Данные пакета | Правило подключения |
|---|---|---|
| Карточки гипотез / пояснения к маршрутам | `cards.json`, читаемый `cards.md` | Ровно C01/C03/C04/C07/C10/C14/C17/C31/C33/C35. Для каждой карточки есть механизм, KEEP, продукт, ресурс, источник, обе ветви и условие следующего решения |
| `step4/netmap`, таблица маршрутов | `program_changes.csv/json`, `airports.csv` | Сначала выбрать hypothesis/scenario/network/variant. `record_type=route_delta` описывает изменение, `dated_flight` — рейс. Эти два вида строк не складывать как вылеты |
| Контекст маршрута / `sources` | `route_context.csv/json`, `route_links.csv` | Гипотеза связывается с парой через `hypothesis_id/route`; carrier/flight/date/type/frequency/price берутся только из подтверждённой строки. Альтернативы остаются контекстом поездки |
| `vs`, варианты 8–12 пар | `strategy/finite_options.csv`, `strategy/option_routes.csv`, `dated_annual.json` | Финальные по составу варианты v4 — owner synthesis, APPROVE_SCOPED EV-MR04; датированная арифметика f99 имеет отдельный scoped EV-MR03. Их календари и денежные границы различаются |
| Смешанная программа | `strategy/mixed11_routes.csv`, `strategy/mixed11_budget.csv` | Конкретный local-only вариант KUF4+OMS8 с общей KUF–OMS, не глобальный mixed optimum; 3 рабочих слота не подтверждают физический парк |
| `fleet_ramp/step5` | `strategy/finite_option_readiness.csv`, ресурсные поля карточек | Дни достаточного агрегатного N(t) — gate, не допуск хвоста/экипажа/базы. Для маленьких продуктов собственные readiness-пробы сохранены в cards.json |
| Бюджет / доля компании | `strategy/budget_components.csv`, `strategy/whole_company_bridge.csv` | Contribution, цена договора, полный добавочный PnL и cash читаются отдельно. Будущий KEEP/рынок/ранг неизвестны |
| Паспорт | `passport_excerpt.md`, `requirements_coverage.csv/md` | Сохранить период, единицу и условие рядом с числом. Статусы покрытия: готово / условно / не выполнено |
| Дополнительные вопросы digital / №2 | `appendix_index.csv/json/md`, `appendices/*.png` | Отдельное приложение: 14 побайтно сохранённых PNG, без изменения основной сети |

`source_index.csv` и `source_manifest.json` задают commit, path, Git blob, SHA256 и размер каждого использованного входа. `claim_pointers.csv/json` связывает тезис с точной строкой; `acceptance.csv/json` отделяет предмет и границу каждого review. `data_dictionary.json` задаёт ключи, единицы и правила соединения. Источники не нужно искать по движущимся веткам: в provenance есть GitHub permalink exact SHA.

## Что зависит от выбора

**City-screening** — исходные оценки городов, веса и порядок в авторском дашборде. Они не пересчитывались в этой поставке. Вес города не является результатом сети и не даёт наличие борта или спроса.

**Proposed programmes** — десять отдельных опытов: неделя синхронизации, местная программа, год сезонных полётов, закрытый контракт, замена двух типов. Их результаты имеют разные периоды и учётные границы. `cards.metrics` содержит точные значения, unit, period, scenario, variant, accounting_boundary и источник каждого показателя. `source_tables` сохраняет исходные строки и остальные чувствительности. Пустое числовое поле не становится нулём.

**Конечные составы v4** — 24 варианта, 205 строк маршрутов, 144 readiness-строки. У каждого состава свой option, сценарий, частоты, рабочие слоты и календарь автора. Выбор одной строки не переносит её годовой contribution на другой календарь и не превращает её в решение команды. `AUTHOR_52_48_CONCENTRATED` отличается от датированных 2027/2028 рядов f99. Историческая поддержка автора — shadow; она не равна правомерному будущему grant.

**Решение команды** ещё не принято: город/сеть, аэропорт для MOW, сценарий поставок и ввода, допустимая загрузка/MCT, остатки кресел, защищённый билет, фактические хвосты/слоты/экипажи, поддержка с тарифом, полный signed KEEP/donor бюджет и cash. Источник владельца модели — Настя/kiruha355; Цири/mput — аудит, Михаил/Mput13 — отдельные командные материалы. Чужая модель не переатрибутируется. Новые v4-рекомендации — синтез владельца методов, не TEAM_ACCEPTED.

## Общие выводы, которые можно сохранять при смене выбора

- Цель №2 относится ко всему бизнесу Red Wings и не имеет срока. 2027–2028 — первый этап. Выбор 8–12 пар не доказывает достижения №2.
- Одна сквозная поездка даёт один тариф и занимает кресло на каждом плече. Общий спрос, хвосты и остатки мест не продаются независимо разным программам.
- SSJ100/RRJ-95 и будущий SJ-100/ПД-8 различаются. Все использованные стоимостные аналоги не становятся подтверждённой экономикой нового типа.
- C07/C33 меняют общие WZ5071/5072; C33/KUF4/OMS4/OMS8 используют общий KUF–OMS рынок. C35 external/own-feed — альтернативы. C31 новые рейсы 5/8 июля не создают same-date feed C35 6/9 июля.
- Положительная дельта сдвига не равна прибыли новой базы. Нулевые дополнительные block-hours не означают нулевую потерю следующего задания. Cash участника не равен экономической добавке компании.
- 359 публикаций дают 215 уникальных направленных отправлений и 144 дубля; 12 конфликтов сохранены отдельно. Это не сумма частот. Для 22 из 45 пар `GAP_NOT_ABSENCE`, а не отсутствие конкурента. Полный тариф с 20 кг и остатки не получены.
- OLD144 остаётся исторической записью без primary raw hash; новое подтверждение — отдельная публикация. Новая запись не восстанавливает отсутствовавшее происхождение старой.
- 25 гипотез в резерве сохраняют историю и следующий тест. Невключение в десятку не является экономическим отказом.

## Приёмка и поздние входы

Network b471, Products 388908, Evidence 38f и Digital d48 имеют свои scoped reviews. EV-MR03 exact994c принял условную арифметику exact f99: 96 dated annual / 2298 weekly LP, same-flight retime и одну неделю C31 / полный контракт C35. Рынок, реальный парк, award, fullPnL и cash этим не приняты. Неудача фиксированной банки не доказывает общую невозможность хаба; retimed week не проецируется автоматически в год.

v4 exact9f0 **APPROVE_SCOPED EV-MR04 exact934a**. Свежий EV-MR04 проверил проекцию десяти карточек, 24 варианта, readiness, mixed11 и бюджетные границы. Это условная арифметика и корректный смысл; market/fleet/fullPnL/cash/future rank/TEAM_ACCEPTED не приняты. Исторический PENDING сохранён отдельным событием в acceptance_events.json; более ранние reviews не расширяются на этот subject. Root intake hashes — проверка целостности входов, не новый независимый verdict. Поздний review оформляется отдельным immutable addendum с subject/review SHA, изменёнными claim IDs и границей; текущий пакет не переписывается. Ссылки на живые ветки не импортируются автоматически.

D03 использует root-correction cb6b282: удалено неподтверждённое «регулярный», charter eligibility UNKNOWN; цифровые числа не менялись. Сам минимальный prose-fix не выдан за повторный независимый review.

Техническое условие H11: текущие N(t) согласованы на неделе 27.12.2027–02.01.2028. Новые поставки 1 января потребуют общей недельной программы до разделения по годам. Это условие handoff для расчёта, не обязательная подпись в UI.

## Воспроизведение

Из любого каталога с доступным Git object store:

```sh
python3 context/28_evening_run_20261110/dashboard_handoff/build.py
python3 context/28_evening_run_20261110/dashboard_handoff/build.py --verify
```

Используется только Python standard library и `git show exactSHA:path`. Скрипт не вызывает модели, allocator, авторский runtime, HTTP, браузер или сервис. Новые зависимости, копия worktree и временный стенд не создаются. `--verify` собирает ожидаемые bytes в памяти, проверяет источники/ключи/ссылки/единицы/границы cash и не пишет файлы. `output_manifest.json` покрывает все остальные файлы пакета, включая исходники сборки. SHA внешнего коммита передаётся после commit/push вне самоссылочного manifest.

Финальная упаковка методики закреплена на `5512f7d474a5db4bb658aae30b10f8b886629861`: [final_handoff](methods_final/final_handoff.md), [freeze](methods_final/freeze.json), [текущие восемь subject→review](methods_final/final_acceptance.csv). Owner freeze — 20:47:39 МСК; общий input cutoff root — 21:15, срок результата — 22:00. Аналитические числа продолжают ссылаться на прежние exact subjects. Исторический PENDING в strategy/acceptance_register.csv сохранён; текущая квалификация — acceptance.csv и acceptance_events.json.

Owner replay допускается только в disposable copy. Для f99 annual_market_caps.csv возможен иной set-derived порядок строк при тех же keyed values; побайтная воспроизводимость всех rerun CSV не обещается, frozen файлы не перезаписываются. Побайтный verify этой сборки относится только к сериализации уже сохранённых exact blobs.
