# Окончательные разрешения после независимой приёмки

При расхождении формулировок первого прохода читать этот файл, README и acceptance/disputed_claims.csv вместе. Числа ledger не изменены.

- `gross` в replay — **gross_before_migration**, не retail gross. Источник inputs.json задаёт сценарный net realised revenue ex recoverable VAT; годовая модель использует подобранные коэффициенты network.csv. Фактический net yield и полный состав удержаний неизвестны. Поэтому первоначальные фразы replay «не налоговый net» нельзя трактовать как доказательство необходимости повторно снять НДС или комиссии. Проверять пересечение с fare/pax proxy. Это семантическая правка с денежным эффектом0, не новый налоговый сценарий.
- Официальный PDF, HTML-страница Росавиации и производный `favt_subsidy_2026.csv` — разные свидетельства; идентичность выгрузки PDF не установлена. Сильный адресный доступ к первичным правилам закончился тайм-аутами. Применимость, единица выплаты, ставка, award, cap, период будущей программы и cash остаются UNKNOWN. Спецтариф для пассажира не равен размеру субсидии перевозчику. Поддержка «на OD» — диагностический сценарий, не юридическое исправление.
- Исходный source round2 просмотрел лишь часть ledger и ошибочно не нашёл две пересадочные записи. Координатор сверил полный CSV, отклонил этот вывод и восстановил корректные строки/формулы. Нет основания считать формулы отсутствующими; первичная рыночная достоверность остаётся отдельно не подтверждённой. Этот проход принят частично, его поиск не расширялся.
- Точный +387722372.71 и контрфакт −706409621.38 приняты независимо. Известные исправления OD, одного билета на пересадку, общего рынка прямых пар и единичного uplift сохраняются. Старую ошибку повторно не исправлять.
- Подтверждены два адресных ограничения: интерпретация48недель и несогласованный direct-shortlist. Ни одно не доказывает новый знак полного PnL или другого победителя. Подтверждённый display patch устраняет6 расхождений округления; +388 он не меняет.
- Статические verify-скрипты methods/acceptance теперь допускают собственный последующий коммит аудита: pin проверяется как источник/предок, точные source-файлы и389хешей продолжают проверяться. К панельному коду эта правка не относится.
