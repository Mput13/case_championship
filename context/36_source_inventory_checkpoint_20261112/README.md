Для OurAirports и части больших архивов исходные полные файлы не хранятся в общем Git. Подтверждение использования — загрузчики, записанные хэши, журнал загрузки и сохранённые производные таблицы. Повторная загрузка ежедневного файла может дать новую версию. Нельзя обещать побайтовую воспроизводимость старого сырого файла, если он не сохранён; отдельно воспроизводятся закреплённые расчётные входы P09.

**Почему здесь допустимы сайты:** аэропорт может публиковать таблицу пассажиров, расписание или прейскурант на странице/PDF, а не в открытой базе с API. Тогда наша работа — сохранить документ и превратить факты в таблицу с периодом, единицей и ссылкой. Структурирование делает сбор воспроизводимым, но не расширяет то, что документ доказывает.

## Наши расчётные таблицы — отдельный слой

`demand_estimates`, `od_pairs`, 39 840 месячных строк P05, 1 958 сравнений P09 и прогнозы 2027–2028 созданы моделью. Они не являются внешними наблюдениями.

Главный пробел: нет полной базы, где строка означает реальную конечную поездку пассажира между двумя городами с ценой и выбором. Поэтому число пассажиров прогнозируется условно, а не считывается из датасета. География, население и частичные потоки поддерживают оценку; её пригодность и диапазон проверяются отдельно.

Яндекс Расписания в старом реестре зарегистрирован, но не подключён. Наличие API в списке источников не разрешает говорить, что данные из него использованы. Аналогично не называем весь каталог БДМО, все найденные URL или платную базу Aviastats приобретёнными входами проекта.
