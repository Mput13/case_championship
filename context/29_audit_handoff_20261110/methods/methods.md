# Methods: проверка пяти шагов на pin 14354571b90545cd0618548481a857bf6b388d4a

Полный **статусный охват реестра**, но не завершённая содержательная приёмка всей модели. `formula_status.csv` содержит все 6990 стабильных ID, `assumption_status.csv` — все 251 ID. 6990 синтаксических узлов сведены в 204 группы файл/функция в `semantic_model_map.csv`; это также не 204 независимые математические модели. Есть отдельные категории бизнес-формул, управления потоком, литералов, подготовки данных, отображения и ошибочно записанных Excel-литералов. Правильная арифметика группы не превращается в подтверждённую истинность каждого её узла.

## Что реально исполнено

`verify_methods.py` проверяет pin через точные Git blobs и SHA256, не через HEAD==pin. Он сверяет 389 защищённых файлов до/после, неизменность inventory, полные множества ID, уникальность, ссылки на группы/файлы, CSV parsing/escaping. Все записи создаёт DictWriter. Внешнего поиска, сообщений, иных ролей, checkout, commit, push и owner rebuild не было. Скрипт пишет только рядом с собой.

## Выводы по пяти шагам

**1.** В текущем рейтинге линейная нормировка по общей совокупности, без log-преобразования. Все пять весовых профилей имеют сумму 100. UNKNOWN получает midpoint либо explicit fill; шкала не меняется после фильтра. Диагностика профилей сохранила опубликованный результат. Дефект M01: при точном равенстве нижней и верхней оценок «худшее место» игнорирует устойчивое разрешение ничьей: второй город имеет ранг 2, но интервал обещает максимум 1. Исправлять нужно Python и JS. Это граничный дефект, не доказанная смена текущей тройки. 75 км — геометрическое допущение; код сначала предпочитает крупный аэропорт, затем ближайший. Это не измеренный рынок поездок и не проверка наземной доступности. Уместность весов и коррелирующих рыночных критериев остаётся решением команды.

**2.** Лог-линейная модель калибруется по сегментам. OD восстанавливается из 31 link counts при заданной пятикоэффициентной форме и маршрутизации; 2044 результата не являются 2044 наблюдениями. LOO измеряет ошибку сегментов, а не истинность OD. Выбор признаков на той же LOO-популяции требует nested проверки. Аналоги и gravity используют общую обучающую информацию; это зависимые оценки. Декабрьская неделя ×52 с загрузкой — прокси годового потока. Гостиничная сезонность 2024 и коэффициент амплитуды не дают независимого наблюдения авиасезонности. Нет основания автоматически подтверждать эти входы по старому VERIFIED_PRIMARY.

**3.** Подтверждены опубликованные арифметические балансы с раскрытым допуском округления. M02: 48 недель концентрируют годовой спрос на 8,333% в неделю относительно 52, хотя описаны как потерянные недели. M03: предварительный shortlist прямых треугольников использует другую цель, чем joint с перетоком/поддержкой; новый победитель не вычислялся. QSI, захват, тариф, LF и конкурентная частота остаются сценарными. M05: 1773 ₽ на немосковский сегмент — условный прокси; применимость программы, тарифные ограничения, award/cash проверяет source-role. Net yield не уменьшается повторно на НДС. Полный PnL и подписанная дельта прежней сети не восстановлены. M08: mandatory экспорт ограничен base/cautious и не равен всей выбранной субсидированной сети.

**4.** M04: при fleet_cap=reserve построитель реально вернул `([], None)`, вызывающая распаковка не поддерживает нулевую сеть. Это ветка задержки/нулевого ресурса, не ошибка чисел нынешних положительных фаз. Дальность — условный screen, не допуск конкретной модификации. Один резерв и недельные часы не доказывают исправность, слоты, экипажи или датированные пересадки (M06). Рост по числу бортов нельзя выдать за прогноз календарного года.

**5.** Roadmap условна; закрытие ниже «порога» не имеет численного/формульного определения (M07). Пилот на трёх лучах не равен расчётной шестилучевой фазе на трёх самолётах. Эффект мер и даты поставок остаются неизвестными. M09: девять Excel qualifiers нужно записывать как строку, а не пустую формулу; влияния на рейтинг не заявлено.

## История и воспроизведение

`source_hashes.csv` сравнивает текущие формульные/assumption файлы с 5905 exact hashes; `historical_scope_receipts.csv` фиксирует прочитанные точные README/resolutions/findings/model-map и cb6b282/f99d6cd readouts. Старые OMS числа не используются как новая приёмка других шагов. Датированные альтернативы f99 имеют другое расписание и scope, их денежные результаты не подставлены в эту панель. Авторство/runtime ИИ из косвенных данных не выводились.

Команда из корня: `python3 -B context/28_end_to_end_audit_20261110/methods/verify_methods.py`. Требуются numpy, pandas и openpyxl (версии в validation). На текущей машине выполнено Python из `/home/mputi/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3`; этот путь не зашит в скрипт. Обычный системный Python не имел pandas, поэтому использован существующий runtime. Полный JS runtime/display replay, повторный fit/LOO, greedy optimality, первичные источники, закрытый OD, договоры, полный бюджет и календарная эксплуатация остаются непроверенными по соответствующим ID. Это явные незакрытые проверки, не доказательства ложности модели.
