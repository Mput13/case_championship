# Закрытие P3 по воспроизводимости проверки

Независимая приёмка приняла деньги/единицы с одним P3: рекурсивный aggregate включал изменяемые статусы делегирования и будущие review outputs. Исторические protection.json/validation.json НЕ перезаписаны.

Координатор восстановил ровно исходный payload delegation.local.json (calculation status=running, без позднего review). При неизменённых остальных файлах исторического набора145 aggregate в точности совпал с0c1d8554c2cfeafc8fcc89c5b38509d3c16e160b6778e4c5bae581d2261bbbc4. Значит причина установлена: служебное обновление статуса, а не изменившаяся цена/расчёт. Полная реконструкция служебного payload хранится отдельно, не заменяет действующий файл статусов.

Минимальная правка verify.py: неизменяемые входы проверяются по135 явным путям и SHA из независимого review/input_content.json; новые review/служебные/выходные файлы не становятся входами. Сохранность1908 прежних tracked paths+content проверяется отдельно без изменяемых stat-метаданных Git index. Новая папкаP39 исключена из прежнего дерева, чтобы проверка работала и после её публикации.

COST_TABLE.csv, RESULT.md, ASSUMPTIONS.md и workings.json совпадают с независимой приёмкой побайтно; финансовых изменений нет. Общая старая фраза ASSUMPTIONS о рекурсивной protection относится к исходной версии и заменена настоящим описанием; исходный независимый вердикт не переименован. Актуальный вывод записывается только в validation_scoped.json;7971 проверка прошла. Это координаторское закрытие локального P3, не повторная независимая приёмка модели.

Машиночитаемые доказательства: closure.json, protection_history_resolution.json и ../calculation/immutable_inputs.json.
