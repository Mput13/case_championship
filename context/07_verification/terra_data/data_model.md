# Схема данных и контроль расчётов

Слои: неизменяемые источники и снимки → нормализованные измерения → сценарии. Все даты и версии сохранять; внешние данные с противоречиями не перезаписывать. Неизвестные значения — `NULL` с причиной и источником; нули — только наблюдаемые нули. CSV-образцы в `samples/` демонстрационные, не полноценная база.

## Согласование единиц

Сначала рассчитать уникальные поездки на каждом OD-маршруте по сценарному допущению. Затем разложить их по плечам: одна пересадочная поездка даёт два пассажиро-сегмента, каждый потребляет кресло своего рейса. `пассажиры_плеча ≤ кресла_выполненных_рейсов` для каждого направления и периода, а не только в сети; кресла конкретного типа и конфигурации, не объявленной семейной модели. Расчёт выручки вести по тарифу за поездку с явно заданными налогами/сборами и трансферами; суммирование полной цены билета по двум плечам удвоит выручку. Долю считать по сопоставимым перевозкам, периоду, территории, охвату и определению. Значения рейсов и тарифов из господдержки не означают, что субсидия равна тарифу, выплачена или получена всеми пассажирами.

Для проверки качества дополнительно контролировать дубликаты снимков, разделение по направлению, расписание/факт, изменения версий и конфликт правил/факта. Текущая демонстрационная выборка S01 частичная из-за `rowspan`; её нельзя считать всей программой или отсутствием других маршрутов. Для проверки модели обучающие и тестовые данные разделять по дате доступности, а похожие или код-шеринговые копии рейса не раскладывать в разные выборки. Не использовать статистику, опубликованную после даты прогноза, при имитации прогноза на эту дату.
