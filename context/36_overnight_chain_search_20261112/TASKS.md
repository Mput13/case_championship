# Недельные цепочки прямых рейсов — ночное исследование

Последнее задание: лучшие пары и **целые недельные цепочки**, три финалиста с расписанием по бортам, таблица KEEP / снять без замены / заменить. Два прохода: широкий быстрый отбор, затем совместный подробный расчёт. Всё только в этой папке, без commit/push и изменений панели/прежних результатов. Указание о локальной работе заменяет прежнюю автоматическую публикацию прогресса.

## Закреплённая база и уже закрытое

Свежие refs в source_pins.json. Локальный HEAD отличается от опубликованного по Git-истории, но содержимое деревьев совпадает: предыдущая публикация прошла через GitHub API. Не merge/reset/rebase/checkout ради исследования. Полный список сохраняемых файлов — protected_files.json. Минимальные P08/P09 в inputs/latest_team; остальное читать git show по pin и сохранять только необходимый источник с provenance.

Использовать P31/P32/P34: оценка1334пар; joint P05/P06 pools/seats; календарь P03; corrected UTC и задержки; source_recovery_new/competitors; свежие P08/SVX/MOSCOW/P09; контроль отмены доноров. Прежний P34 дал qualified_new_routes=0, а не доказанную пятёрку. Отсутствие строки RW не доказательство отсутствия рейса. Маркетинговый рейс с пересадкой не own nonstop, но его пассажиры не новые для RW.

Не повторять ошибки:

- Нельзя считать прибыль новой цепочки эффектом снятия убыточного в модели донора: joint KEEP / remove-only / replace строятся отдельно, с перераспределением оставшихся пассажиров. Не вычитать донора/переток второй раз.
- Старый noadj стресс асимметричен: он убирает два дохода треугольника и сохраняет весь доход челночного рынка. Не основной рейтинг. Основное сравнение на одном мире спроса/затрат; слабые соседние продажи — отдельная идентифицированная чувствительность финалистов, не вывод «треугольники хуже».
- P31 short horizon frequency bug: один вылет за7дней получал0.25/week. Для основного отбора использовать полный февраль2027 с4повторами недельного шаблона; адаптация к полным другим месяцам/вводу SJ должна сохранить корректный exposure, спрос не умножать повторно.
- P33 исходные clocks/FOLLOW ошибочны. Использовать исправленные P34/P32 UTC aware данные; каждая дата/пояс проверяются. Полночь не обнуляет задержку.
- 8BH/day — производственная диагностика выбранной модели, не FDP/закон/паспортная дальность. Его нельзя молча ослабить; отдельно календарная физика, ресурсный screen и неподтверждённые crew/MRO/слоты/AFM.

## Роли

1. Недорогой market: только адресный календарь RW/конкурентов, новизна, тариф/OD/сезонность/время. Сначала новые team-данные и завершённые P34 источники, затем реальные внешние запросы по решающим пробелам.
2. Недорогой operations/cost: только текущие базовые задания/aircraft support/turns/станции/ночёвки/тарифы топлива и avoidability. Не дублировать поиск конкурентов/цен билетов.
3. Sol проход1: свежая дельта, договор расчёта и baseline, граф и генератор путей/дней/часов/частот/действий, широкий тонкий screen с coverage/rejection/shortlist. Не ждать исследователей и не читать незавершённые файлы.
4. Sol проход2 после completed источников/прохода1: подробный совместный расчёт лидеров, ресурс/поставки/задержки/пороги, три разные недельные цепочки и топ5пар.
5. Astra: отдельно проверка финалистов/снятых заданий/двойного счёта/физики. Один основной проход и адресные исправления существенного, без повторного глобального аудита.

## Что требуется перебрать и зафиксировать

Конечный набор аэропортов содержит Москву(физические ZIA/DME отдельно, один городской OD), SVX, кандидатов P34 и другие узлы из готовых P08/пар. Не создавать новую базу в каждом городе. Начальные самолёты только в обоснованных сценарных позициях. Возможны RT, обе ориентации треугольников, цепи4+плеч. Каждое плечо — отдельный рынок с обоснованием либо явно платный ferry с нулевой продажей. Нет SVX→SVX фиктивных рейсов.

Дни1–7, несколько локальных окон, частоты1/2/3/5/7 в широком отборе (если часть невозможна — записать почему). Действия: вставка в **явно заданное** свободное окно, перенос, снять1, снятьнесколько, обмен между двумя совместимыми бортами. Неизвестная занятость не означает свободу. Для swap нужны физическая встреча/продолжение позиций или оплаченный перегон. Если baseline неполный, внешние часы остаются заблокированы или явно отдельным IDLE_SCENARIO с unknown occupancy loss; не обещать бесплатный налёт. Все затронутые прежние задания имеют stable IDs и action map keep/move/remove/swap. У каждого remove/move — revenue/avoidable cost и ограничения/потери, либо UNKNOWN и порог.

Нужна оболочка действующего парка минимум E1(SVX) и E2(условные SVX+обоснованная Москва) плюс отдельный резерв. Регистрации/реальное освобождение могут быть UNKNOWN: это не опубликованный свободный флот. Одинаковая оболочка для KEEP/remove/replace. При отсутствии подтверждённого московского борта считать его сценарным с неизвестным прежним заданием/порогом D либо платный перевод изSVX, а не бесплатный ресурс. B777 не перераспределяются. Другие типы — отдельные допустимые по ТЗ условия, не универсальная замена RRJ.

SJ-100 — только после H2 2027 и **сценарного ввода**, не поставки. Взять прежние явно иллюстративные S0/S1/S1D6, фактические даты/числа не обещать. Доступность и эксплуатационные параметры PD8 не приравнивать к RRJ. Показать действующий парк, поставки, задержку/нет поставок отдельно. Для месячных сравнений использовать действительный календарь, не48/52/фиктивное равенство дней.

## Экономика и допуск

Три состояния считаются совместно; remove-only для комбинации переносов/обменов сохраняет те же изменения старого расписания без новых рейсов. Whole-company Δ формируется по всем плечам/потерянным продажам/перетоку/избегаемым расходам. Fixed lease/зарплата не автоматически избегаемы; ночёвка/парковка/позиционирование/резерв/потери переноса не бесплатны. Общие затраты отмены в remove и replace сокращаются; различия показываются. Фактический fullPnL/cash/F/реальные продажи при отсутствии данных NULL, не0. Support/cargo main0, подтверждённые механизмы отдельно, ничего гарантированного.

Наблюдаемый OD/чистый тариф/цели поездки не заменять аэропортовым потоком/креслами×LF/популяцией/предприятием. P05priors, симметрия и месячный профиль — сценарии. Если нет данных по дням/часам, равномерность явно сценарна; отсутствие временной эластичности не позволяет присвоить доход удобному слоту. Новые продажи/переток не считать дважды. DME/ZIA делят один city pool. Максимально возможная выручка при100креслах — только верхний screen, не спрос.

Проверить структурно, может ли осторожный cost/yield вообще дать положительный самостоятельный вклад при полной загрузке: если нет, широкий поиск это не исправит. Показать порог топлива/netfare/минимальных продаж и происхождение затрат, не подгонять тариф ради прибыли. Сравнивать изменение к лучшей **допустимой** альтернативе, включая remove-only; «меньше теряет» не достаточная рекомендация запуска.

По финалистам: два направления, слабые соседние продажи (с явно определённым общим/индивидуальным стрессом), holds30/60/120 на новых плечах по отдельности, каждый следующий рейс и crew/TO/slot gates. Не придумывать вероятность/цену минуты/автоотмену, ожидание на земле не blockhour cost. Фактический слот остаётся UNKNOWN от соседнего опубликованного рейса.

## Результат

Короткий утренний файл: топ5пар с честным статусом новизны;3лучших различных недельных цепочки по бортам; единая таблицаKEEP/remove/replace и разложение эффекта; первая цепочка для проверки и её q/netfare/cost gates; что именно меняет осторожный выбор. При неидентифицированном результате — три кандидата/варианта для проверки, а не три готовых запуска. Приложить код и logs реальных прогонов, конечное покрытие перебора (узлы/время/дни/частоты/actionsets/rejected), sources/assumptions/AI-use. Никаких миллиона ID/непрозрачных паков. Работать до завершения задач, а не ради непрерывной активности.
