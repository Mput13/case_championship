# Red Wings Travel Assistant

Запрос 13.11.2026: изучить аналоги, транспортные коннекторы и агентный движок, быстро подготовить веб-прототип для демонстрации. Российские перевозки; генерация DeepSeek через `https://api-ai.mai.ru`. Точный model ID и протокол проверяются после получения ключа. Pi рассматривается как агентный движок; Python не является синонимом Pi.

Два сценария: поездка по городам и периоду; дорога до/после уже выбранного рейса Red Wings. Адрес — необязательное уточнение. Минимум один подтверждённый рейс Red Wings в каждом предлагаемом варианте. Наземные участки, несколько вариантов, источники, ссылки для дальнейшего выбора/покупки.

Расписание, наличие мест, цена и оплаченный билет — разные состояния. Модель не придумывает рейсы и пересадки. Локальные сохранённые ответы источников разрешены только как явно обозначенный снимок с датой; они не подтверждают текущее наличие или цену. Нет автопокупки, оплаты или обещания защищённой стыковки отдельных билетов.

## Предварительный контракт прототипа

Node.js ESM, без обязательных крупных зависимостей; движок агента выбирается после исследования. Сервер и доменная логика отделены от UI. API same-origin, секреты только на сервере.

`GET /api/health`: `{status, model_configured, schedule_mode, model?}`; без секретов.

`GET /api/examples`: `{examples:[{id,label,request}]}`; только реальные поддержанные примеры с областью покрытия.

`POST /api/plan`: `{mode:"trip"|"flight", origin, destination, date_from, date_to, preference:"balanced"|"fastest"|"fewest_changes", message?, flight_number?, flight_date?}`. Города — строки, даты ISO. Диапазон ограничен сервером. Поля выбранного рейса обязательны только для режима flight.

Ответ: `{status:"ok"|"no_routes"|"needs_data"|"error", message?, data_mode:"live"|"snapshot"|"unavailable", checked_at?, coverage_note?, variants:[], assistant?:{status,text}, sources:[]}`.

Вариант: `{id,title,summary?,departure?,arrival?,duration_minutes:null|number,total_price:null|number,currency:"RUB",price_note?,warnings:[],legs:[]}`.

Участок: `{mode:"plane"|"train"|"suburban"|"bus"|"taxi"|"walk"|"ground",origin,destination,departure:null|string,arrival:null|string,carrier:null|string,flight_number?,price:null|number,status:"scheduled"|"suggestion"|"unknown",source_name?,source_url?,links:[{label,url}]}`.

Присутствие Red Wings проверяется по источнику/коду перевозчика в доменной логике. Непроверенные наземные рекомендации имеют `suggestion`, без выдуманных датированных рейсов и стоимости. Нет числа общей длительности, если какой-либо необходимый участок неизвестен. Сервер вычисляет варианты; LLM может разбирать ввод и объяснять только предоставленные факты. До проверки ключа генерацию не запускать.

## Уточнения после исследования Trip&Fly и треда презентации

Проверка Trip&Fly: `research/tripfly.md`. Платформа «Инновационная мобильность» подтверждает партнёрские API и White Label, но доступа/договора/схем у проекта нет. Это кандидат для последующего билетного контура. В прототипе не показывать фиктивные оплату, единый заказ или активную страховку. Добровольный полис и конкретное покрытие должны подтверждаться источником. Полезная задача ассистента — подробное планирование трансфера: FAQ Trip&Fly оставляет его пассажиру.

Контекст презентации: `research/presentation_context.md`. Актуальна v10, не менять её. Будущая предлагаемая сеть 2027–2028 и наблюдаемые рейсы — разные режимы; сценарное предложение нельзя выдавать за бронируемый рейс.

МАИ: verified TLS и `GET /v1/models` успешно проверены координатором. Доступны точные ID `DeepSeek-V4-Flash` и `deepseek-v4.1-flash`. Для первого прототипа выбран `deepseek-v4.1-flash`. Сервер использует Russian Trusted Root CA; системное доверие не менять. Безопасный host-scoped контекст и fingerprint — `research/mai_tls.md`; authenticated GET receipt — `receipts/mai_models_verified.json`. Секрет только у координатора, не искать.
