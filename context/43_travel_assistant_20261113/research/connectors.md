Проверено 13.11.2026. Прямые HTTP-проверки выполнены без API-ключей, авторизации и отправки cookies; время и хеши ответов — в [connectors_sources.json](connectors_sources.json). ## Практическая рекомендация

Для быстрого прототипа выбрать **Яндекс Расписания для датированных междугородних сегментов, 2ГИС для внешней навигации и официальный сайт Red Wings для покупки**. Первый рабочий режим — публичный бесплатный помощник по расписанию: минимум один опубликованный рейс Red Wings, несколько проверяемых сочетаний транспорта, источник каждого сегмента, цена и наличие со статусом `unknown`, когда подтверждения нет. Для расчёта поездки от адреса до адреса добавить **один ключ 2ГИС с доступом к Geocoder API и Routing API**. Это технически два продуктовых доступа/ключа вместе с Расписаниями. Получение ключа не подтверждает право на произвольное хранение и переработку данных: условия ниже должны определять включаемые функции.

**Без ключей сейчас можно показать два подтверждённых примера рейсов и навигационные ссылки, но нельзя обещать полный поиск по России на произвольный период.** Официальное табло Red Wings доступно текстом, однако охватывает вчера/сегодня/завтра. Исторические JSON пригодны для разработки адаптера и выбора начальных узлов, не для выдачи актуальных поездок. Предзаполненная ссылка на покупку конкретного рейса Red Wings не подтверждена; доступна проверенная точка входа `/booking/`. Если acceptance требует именно покупку выбранного рейса без повторного ввода, эта часть остаётся открытой до получения документированного контракта от авиакомпании/партнёра.

Для коммерческого помощника с собственным ранжированием и объединением источников заранее согласовать соответствующее использование с поставщиками. Практический следующий шаг — получить новый ключ Расписаний для допустимого публичного режима и новый демо-ключ 2ГИС; продажу оставить на стороне перевозчиков. Это рекомендация для реализации, ключи в этой работе не создавались.

## Контракт Яндекс Расписаний

Документированный базовый URL: `https://api.rasp.yandex-net.ru/v3.0/`. Яндекс рекомендует его вместо `api.rasp.yandex.net`. Все методы — GET; ключ передаётся как `apikey` либо в заголовке `Authorization` без придуманного префикса Bearer. [Доступ](https://yandex.ru/dev/rasp/doc/ru/concepts/access), [актуальный домен](https://yandex.ru/dev/rasp/doc/ru/reference/list-stations-route).

| Метод | Минимальный запрос, без ключа в примере | Использование |
|---|---|---|
| [`carrier/`](https://yandex.ru/dev/rasp/doc/ru/reference/query-carrier) | `?code=WZ&system=iata&format=json` | Получить `carriers[]`, выбрать Red Wings по идентичности/кодам; ответ IATA может содержать несколько перевозчиков |
| [`search/`](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point) | `?from=SVX&to=KZN&system=iata&date=2026-11-14&transport_types=plane&transfers=false&limit=100&offset=0` | Поиск датированных сегментов |
| [`schedule/`](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-on-station) | `?station=SVX&system=iata&date=2026-11-14&event=departure&transport_types=plane` | Исходящие рейсы конкретного аэропорта; начальные узлы берём из небольшого проверенного справочника |
| [`thread/`](https://yandex.ru/dev/rasp/doc/ru/reference/list-stations-route) | `?uid=<свежий uid>&date=2026-11-14` | Остановки/детали; UID получать заново из поиска/расписания, не считать постоянным |
| [`stations_list/`](https://yandex.ru/dev/rasp/doc/ru/reference/stations-list) | `?format=json&lang=ru_RU` | Иерархия стран, регионов, городов, станций; около 40 МБ по документации, не скачивать на каждый пользовательский поиск |
| [`nearest_stations/`](https://yandex.ru/dev/rasp/doc/ru/reference/query-nearest-station) | `?lat=56.838011&lng=60.597474&distance=30&transport_types=plane&limit=50` | Станции около координат; радиус в км. Это географическая близость, не время проезда |
| [`copyright/`](https://yandex.ru/dev/rasp/doc/ru/reference/query-copyright) | `?format=json` | Баннер, уведомление и ссылка для обязательного указания источника |

Поиск принимает **одну дату**, период перебирается по дням; без `date` выдаются прямые рейсы на все даты, пересадки не включаются. Для городов используем `c...`, для конкретных станций `s...`; аэропорт и агрегат города не взаимозаменяемы. `transfers=true` добавляет найденные пересадки, но не даёт гарантии полноты произвольных мультимодальных сочетаний. Страница поиска — до 100 результатов, пагинация через `offset` и `pagination.total`. Документированного фильтра `carrier=WZ` в поиске нет: перевозчика проверяет наш адаптер. `tickets_info.places[].price` содержит `whole`/`cents`; `et_marker` описывает возможность электронного билета, не подтверждает кресло для пользователя. [Спецификация поиска](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point).

В историческом `yandex_hub_schedules.json` Red Wings имеет `code=617`, `iata=WZ`, `sirena=ИН`, `icao=RWZ`. **617 — только начальное историческое соответствие**: текущий успешный `carrier/` с ключом не выполнен. Нельзя отбирать компанию исключительно по строковому префиксу номера: встречаются разные системы кодирования. Нужна идентичность перевозчика и датированный рейс; для спорного codeshare отдельно подтверждать фактического оператора первичным источником.

Для собственного построения сочетаний надёжнее сначала собрать отдельные датированные плечи и явно проверить стыковки. Полная структура ответа с пересадками без ключа здесь не проверена; не закладывать выдуманное поле `details` в обязательный контракт. Непонятную структуру возвращать как `schema_unsupported`, а не как отсутствие рейсов.

### Условия, квоты и атрибуция

Стандартные [условия Расписаний](https://yandex.ru/legal/rasp_api/ru/) разрешают использование в открытом бесплатном сайте/приложении; обычная регистрация допустима. Платный или закрытый проект требует письменного согласования. Это не общее запрещение использовать API юридическому лицу. Пункты 2.3.3 и 3.2.4 ограничивают функциональность, обработку и сохранение данных; временный кэш разрешён для работы сервиса. Собственный постоянный транспортный граф, перераспространение данных и коммерческое объединение источников не считать автоматически разрешёнными.

Для десктопного сайта нужен баннер из `copyright/` рядом с данными и указание источника в помощи; для мобильного сайта — текст с активной ссылкой рядом с данными и в помощи. Предусмотреть атрибуцию в компоненте результата, не прятать её за единственной общей ссылкой в footer. [Формат копирайта](https://yandex.ru/dev/rasp/doc/ru/reference/query-copyright).

**Числовая актуальная суточная квота Расписаний не подтверждена.** На проверенных страницах доступа/условий нет подтверждения часто цитируемого лимита «500 в сутки»; не зашивать его как действующий тариф. До запуска узнать квоту нового ключа в кабинете/у поддержки. В адаптере обязательны настраиваемый бюджет запросов, ограничение периода, остановка при исчерпании и отдельный статус `quota_exhausted`. Это рекомендация реализации; лимит 100 результатов в ответе не является суточной квотой.

## Контракт городской маршрутизации

### 2ГИС: рекомендуемый дополнительный API

Прямое геокодирование: `GET https://catalog.api.2gis.com/3.0/items/geocode?q=<город,адрес>&fields=items.point,items.geometry.centroid&key=<NEW_KEY>`. Координаты — `result.items[].point.{lat,lon}`. Не запрашивать платные расширенные поля, если они не нужны. [Geocoder API](https://docs.2gis.com/api/search/geocoder/overview).

Общественный транспорт: `POST https://routing.api.2gis.com/public_transport/2.0?key=<NEW_KEY>`, `Content-Type: application/json`:

```json
{
  "source": {"point": {"lat": 56.838011, "lon": 60.597474}},
  "target": {"point": {"lat": 56.743108, "lon": 60.802728}},
  "transport": ["pedestrian", "bus", "metro", "suburban_train", "aeroexpress"],
  "locale": "ru",
  "enable_schedule": true,
  "max_result_count": 3
}
```

Для планирования добавлять `start_time` как Unix seconds нужного отправления; без него используется текущее время. Ответ содержит варианты с `movements`, временем/расстоянием, пересадками и, если доступны, `schedules`. Проверять `pedestrian`: при недоступном транспорте возможен полностью пешеходный ответ; это не подтверждение автобуса. Спецификация: [POST /public_transport/2.0](https://docs.2gis.com/api/navigation/routing/reference/public_transport). Для автомобиля/пешком — другой endpoint: [POST /routing/7.0.0/global](https://docs.2gis.com/api/navigation/routing/reference/routing).

Демо-ключ выдаётся один раз на месяц; [общие демо-лимиты](https://docs.2gis.com/platform-manager/subscription/pricing) — 1 000 запросов Routing и 1 000 Geocoder. Для подписки указано 600 единиц/минуту для этих сервисов, месячный объём выбирается отдельно. [Демо](https://docs.2gis.com/platform-manager/demo-key). Ограничение демо-маршрута — 50 км; тест на дальнюю дорогу в аэропорт может упереться в демо, а не в отсутствие дороги. [Начало работы](https://docs.2gis.com/api/navigation/routing/start).

Не считать демо бессрочной бесплатной коммерческой лицензией. Опубликованные [справочная](https://law.2gis.ru/webapi-offer) и [картографическая](https://law.2gis.ru/offer-cartographic-webapi) оферты требуют указания «2ГИС» со ссылкой и в п. 3.1 не предусматривают кэширование продуктов. Поэтому начальный адаптер не сохраняет ответы в постоянную базу; применимость оферты к выбранному Routing-продукту, обработку для сравнения поездок и разрешённое хранение закрепить в условиях конкретной подписки. Точный платёж для нашего проекта не установлен.

### Яндекс: HTTP доступен, управление браузером для API не нужно

Документированный запрос:

```text
GET https://api.routing.yandex.net/v2/route
  ?apikey=<NEW_ROUTER_KEY>
  &waypoints=56.838011,60.597474|56.743108,60.802728
  &mode=transit
```

`departure_time` — Unix seconds, не может быть в прошлом; для транспорта смысл и горизонт расписаний нужно проверить отдельным успешным запросом, документация описывает параметр прежде всего через прогноз пробок. `results` управляет количеством результатов. Для `driving/truck` в подробной спецификации максимум 50 точек, для остальных режимов 25; общая страница продукта упоминает 100 для автомобиля — для прототипа следовать более строгой спецификации. [Формат запроса](https://yandex.ru/maps-api/docs/router-api/request.html), [ответ](https://yandex.ru/maps-api/docs/router-api/response.html). Реальное покрытие `transit` для выбранных аэропортов без ключа не проверено.

[Быстрый старт](https://yandex.ru/maps-api/docs/router-api/quickstart.html) требует отдельный продукт «Получение деталей маршрута». [Тариф тестового периода](https://yandex.ru/dev/tariffs/doc/ru/router/prices/): до 7 суток, 100 **ответов**/сутки бесплатно. Пример опубликованного стандартного коммерческого тарифа — 20 800 ₽ за 30 дней при 1 000 ответов/сутки; не считать бесплатным постоянным API. При нескольких ответах на запрос тарифицируется каждый ответ. [Условия Router](https://yandex.ru/dev/tariffs/doc/ru/router/terms/) различают стандартную лицензию с временным кэшем до 30 дней после оплаты и расширенную с хранением на срок лицензии; ограничивают изменение/сортировку полученных данных. Проверить договор для собственного ранжирования вариантов.

JS API нужен, если карта встроена в наш интерфейс: загрузить `https://api-maps.yandex.ru/2.1/?apikey=<NEW_JS_KEY>&lang=ru_RU`, затем `ymaps.multiRouter.MultiRoute` с `params.routingMode='masstransit'` (либо `auto`, `pedestrian`, `bicycle`). Это JavaScript, исполняемый на странице приложения, а не разрешение автоматизировать чужой UI. [Подключение](https://yandex.ru/dev/jsapi-v2-1/doc/en/v2-1/dg/concepts/load), [параметры](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/IMultiRouteParams).

Адреса требуют геокодирования: актуальная документация даёт `GET https://geocode-maps.yandex.ru/v1?apikey=<NEW_GEOCODER_KEY>&geocode=<адрес>&lang=ru_RU&format=json`. [Контракт](https://yandex.ru/maps-api/docs/geocoder-api/request.html). Бесплатный Геокодер по п. 6.6 [общих условий](https://yandex.ru/legal/maps_api/ru/) связан с показом результата в Яндекс JS API и имеет 1 000 запросов/сутки; это не свободный серверный справочник координат для чужой карты. Условия также требуют сохранять копирайты/переход в Карты и ограничивают переработку данных. Доступы Geocoder, JS и HTTP Router не считать одним взаимозаменяемым ключом.

| Навигация Яндекс web | `https://yandex.ru/maps/?rtext=<lat1>,<lon1>~<lat2>,<lon2>&rtt=mt` | Точки и вид транспорта; для `auto`, `pd`, `bc` меняется режим. Дата поездки этим проверенным контрактом не задаётся |
| Яндекс mobile | `yandexmaps://maps.yandex.ru/?...&client=<id>&signature=<signature>` | Для регулярного запуска приложения нужен отдельный client/RSA-ключ: без подписи после 5 переходов за 24 ч на устройстве действуют ограничения. Не путать с Router/JS API key |
| Покупка Red Wings | `https://flyredwings.com/booking/` | Вход в официальную продажу. **Выбранные рейс/дата/пассажиры не подтверждены как предзаполненные** |
| Покупка РЖД | `https://ticket.rzd.ru/` | Вход в пассажирскую покупку; документированный актуальный предзаполненный URL в этом исследовании не установлен |
| Покупка Туту | `https://www.tutu.ru/poezda/` | Вход в поиск поездов; партнёрский редирект/комиссионный идентификатор требует подключения |

Источники навигации: [2ГИС deeplinks](https://help.2gis.ru/question/razrabotchikam-zapusk-ideystviya-vmobilnom-prilozhenii-cherez-deeplink), [Яндекс web](https://yandex.ru/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-web), [ограничения mobile](https://yandex.ru/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-commercial-use), [подпись](https://yandex.ru/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-commercial-use-signature). У Яндекса `rtext` использует **широту,долготу**, а у 2ГИС points — **долготу,широту**. Поля ссылок кодировать URL-encoder; не менять порядок координат по аналогии с другим продуктом.

В HTML официального flyredwings наблюдаются `engineURL='https://flyredwings.com/booking/'` и GraphQL URL `https://wz.webskyx.com/graphql/query/nemo`. **Наличие этого URL в странице не делает его документированным публичным API.** Запросы к нему не отправлялись; сериализация `#/search/...` не установлена как стабильный партнёрский контракт. Не собирать самодельный purchase deep link и не показывать вымышленное подтверждение его работы. Открытая [страница для агентов](https://flyredwings.com/agents/) предлагает договорное сотрудничество, тарифы и запрос мест; публичной спецификации автоматической продажи там не найдено.

Официальный поставщик РЖД [описывает подключение](https://www.platform.smarttravel.ru/) через договор, тестовый доступ и API. На его [странице правил для агентов](https://platform.smarttravel.ru/blog/legalnye-sposoby-prodazhi-biletov) прямо разделены пассажирские каналы и договорные API/White Label; автоматизированный доступ к `ticket.rzd.ru` для агентской работы запрещён. Для второго этапа запросить read-only поиск с ценой и наличием, station dictionaries, правила тарифа и booking/deep-link контракт. Контент Red Wings в конкретном подключении отдельно подтвердить: общая реклама авиаконтента не доказывает доступность WZ.

У Туту обнаружен документированный **адаптер Travelpayouts**, а не полноценный публичный API продажи Туту:

```text
GET https://suggest.travelpayouts.com/search
  ?service=tutu_trains&term=2000000&term2=2064130&callback=n
```

Документация предупреждает, что данные не передаются в реальном времени. В проверенном ответе JSONP присутствуют `trips`, времена, номера поездов и `categories[].price`, но нет даты и подтверждения кресел на нужный день. Парсить JSONP без `eval`; использовать только для вспомогательного виджета при соблюдении партнёрских условий. [Документация поставщика адаптера](https://support.travelpayouts.com/hc/ru/articles/360020147791-API-%D0%BE%D1%82-Tutu-ru). `partner.tutu.ru` сейчас перенаправляет на [партнёрскую программу](https://advcake.ru/lp/tutu/); это не открытая спецификация актуального инвентаря. Публичный self-service API бронирования Туту не найден, его отсутствие как факт не утверждается.

## Минимальный набор доступов

| Режим | Новые доступы | Ограничение |
|---|---|---|
| Показ подготовленных проверенных примеров + внешняя навигация | 0 | Ограниченный демонстрационный набор; неизвестные цены/места. Не полный живой поиск |
| Датированный поиск между городами и внешняя навигация | 1 ключ Яндекс Расписаний | Допустимый бесплатный публичный режим; коммерческое использование/собственная обработка по согласованному объёму прав |
| Расчёт адрес — аэропорт — аэропорт — адрес | Тот же ключ + 1 ключ 2ГИС с Geocoder и Routing | Демо/подписка, фактическое покрытие и условия обработки. Два ключа технически, несколько продуктовых разрешений |
| Полностью на Яндекс для городской части | Расписания + доступ Router + доступ Geocoder; JS при своей карте | Не обещать один общий ключ для разных продуктов; физическое объединение ключей проверяется в новом кабинете |
| Доступные тарифы и наличие для продажи | Договорный билетный API/WL и выданные credentials | Обычный ключ расписаний/карт этого не заменяет; тесты поиска и продажи — отдельная приёмка |

## Предлагаемый контракт нашего адаптера

Это проектное решение, не спецификация поставщика. Сначала поддержать небольшой перечень аэропортов/узлов с проверенным соответствием кодов, затем расширять. Не объявлять покрытой всю Россию по двум примерам.

```json
{
  "from": {"city": "Екатеринбург", "address": null, "point": null},
  "to": {"city": "Казань", "address": null, "point": null},
  "window": {"from": "2026-11-14", "to": "2026-11-14", "semantics": "departure"},
  "passengers": {"adults": 1, "children_ages": []},
  "required_carrier": "WZ",
  "allowed_modes": ["plane", "train", "suburban", "bus", "walk", "taxi"],
  "max_options": 3
}
```

Обработка: разрешить города/адреса в конкретные точки и станции → получить датированные плечи → включить хотя бы одно подтверждённое плечо Red Wings → проверить наземные переезды, терминалы, календарь и запас до регистрации → убрать невозможные стыковки → показать до трёх существенно разных вариантов. Если обычный поиск A–B не вернул WZ, проверить ограниченный набор промежуточных узлов, не обещая полноту. Допустимость объединения/ранжирования определяется лицензиями источников. Бюджет запросов и семидневное ограничение начального периода — настройки прототипа, не ограничения API.

Для каждого `leg` нужны: `mode`, конкретные `from/to` и коды станций/аэропортов, `departure/arrival` ISO 8601 с UTC offset, `carrier`, `flight_or_train_number`, `source_url`, `fetched_at`, `source_updated_at|null`, `schedule_status`, `price`, `availability`, `navigation_links[]`, `purchase_links[]`. Дополнительно `operating_carrier_status`: код продажи без подтверждённого оператора не превращать в доказательство выполнения Red Wings.

Деньги: `price={amount:null,currency:'RUB',status:'unknown'}` по умолчанию; для справочного тарифа — `indicative`, для датированного ответа продавца — `quoted` с временем и составом тарифа. Если не оценено хотя бы одно платное плечо, `total_price=null`; отдельно можно вывести `known_subtotal`. Не ранжировать как «самый дешёвый» вариант с неизвестной общей стоимостью. `availability='unknown'` до отдельного ответа продавца для даты, состава пассажиров и класса; кэшированная цена не меняет этот статус.

Ссылка: `{kind:'navigation|purchase',target:'route|search|offer|entry',url,prefill_verified:false,validation:'documented_format|http_checked|ui_checked'}`. Ответ HTTP 200 формы покупки подтверждает только `target=entry`; для `offer` нужны предложение продавца и срок его действия. Ни одной ссылки здесь не присваивается `ui_checked`.

Состояния поиска различать: `ok`, `no_matches_in_checked_scope`, `coverage_partial`, `key_required`, `quota_exhausted`, `upstream_unavailable`, `schema_unsupported`. Ошибка/непокрытая станция не равна отсутствию транспорта. `schedule_status=published` не означает `operated` и не гарантирует выполнения будущего рейса.

Варианты могут быть «автобус + WZ + городской транспорт», «автомобиль/такси + WZ + городской транспорт», «поезд до соседнего аэропорта + WZ + наземный участок», если соответствующие плечи подтверждены. Цена такси не выводится из автомобильного Router. Не создавать три карточки из одного и того же рейса без существенной разницы. Независимые билеты обозначать как самостоятельную пересадку; пересадка в выдаче расписаний не создаёт единой гарантированной перевозки.

## Бесплатные проверки

### Доступ к API

Проверки 13.11.2026, около 15:32 МСК. Полные URL, тела запросов, коды, точные ошибки и SHA-256 сохранены в JSON.

| Проверка без ключа | Наблюдение | Вывод |
|---|---|---|
| Расписания `carrier/?code=WZ&system=iata` | HTTP 400, `Не указан ключ` | Текущая идентичность carrier через API не проверена |
| Расписания SVX → KZN, 14.11.2026 | HTTP 400, `Не указан ключ` | Нет успешного живого ответа расписаний; это не отсутствие рейса |
| Яндекс Router, `mode=transit` | HTTP 401, `Parameter 'apikey' is missing.` | Нужен новый ключ; покрытие/геометрия не проверены |
| 2ГИС `public_transport/2.0`, POST | HTTP 403, `{"type":"forbidden","message":"empty_key"}` | Выполнен только неавторизованный расчётный запрос, не создание заказа |
| Документированный адаптер Туту/Travelpayouts | HTTP 200, JSONP с поездами/категориями | Без ключа отвечает; выбранная дата и наличие не подтверждаются |
| `https://flyredwings.com/booking/` | HTTP 200, оболочка формы | Только точка входа в продажу, без поиска цены или оформления |

### Пример 1: Екатеринбург → Казань, 14 ноября 2026

Прямой GET [официального табло Red Wings](https://flyredwings.com/flight-board/) в 15:40 МСК, вкладка **14.11**, содержит WZ 1067, Кольцово **08:30** → Казань **08:10** местного времени. [Кольцово](https://ar-svx.ru/schedule/) независимо публикует WZ-1067 по четвергам/субботам в период 29.10–28.11 с теми же временами; 14.11 — суббота. Это подтверждение опубликованного рейса, не мест в продаже.

Нормализация: `2026-11-14T08:30:00+05:00` → `2026-11-14T08:10:00+03:00`, **1 ч 40 мин**. Вычитание местных часов без поясов дало бы ошибку.

[Страница аэропорта о транспорте](https://ar-svx.ru/how-to-get/to/bus/) описывает автобус №65 от ж/д вокзала и поезд №6038 07:12–07:53 ежедневно. Это справочная страница без подтверждённой даты действия тарифов: указанные там 33 ₽ не принимаем за актуальную котировку. Поезд прибывает за 37 минут до вылета. В [правилах Red Wings, п. 6.4.5](https://flyredwings.com/upload/PDF/pravila_perevozki_2025_10_01.pdf#page=33) регистрация и оформление багажа в РФ заканчиваются за 40 минут: **вариант с поездом №6038 отклоняется для пассажира, которому нужна стойка регистрации/сдача багажа**, ещё до учёта перехода в терминал. Для заранее зарегистрированного пассажира без багажа выполнимость также не подтверждена: [посадка](https://flyredwings.com/check-in-rules/) заканчивается за 30 минут, нужен переход и досмотр.

В прототип можно передать два кандидата для последующей проверки — ранний автобус/городской транспорт и автомобиль/такси к тому же реальному WZ. Их время от адреса, наземная часть в Казани, стоимость и наличие **не проверены**. Пример координатной [ссылки 2ГИС к Кольцово](https://2gis.ru/directions/tab/bus/points/60.597474,56.838011%7C60.802728,56.743108) показывает формат передачи точек из бесплатного запроса; точность входа в терминал не подтверждена геокодированием. [Покупка Red Wings](https://flyredwings.com/booking/) требует ввода параметров. Полный мультимодальный E2E этого примера не заявляется.

### Пример 2: Санкт-Петербург → Москва, отправление 13 ноября 2026

Тот же прямой GET табло в 15:40 МСК, вкладка **13.11**, содержит WZ 1122: Пулково **22:40** → Внуково **14.11 00:00**. Оба города UTC+3; длительность **1 ч 20 мин**. Это полезный пример для границы периода: при `window.semantics=departure` запрос на 13.11 его включает; требование прибыть до конца 13.11 его исключает. Источник — [официальное табло](https://flyredwings.com/flight-board/), не прошлый JSON и не индексированная копия страницы.

Ночной наземный транспорт из VKO нельзя добавлять как будто он точно работает в момент прибытия; сначала запросить время после выхода из аэропорта и проверить конкретные рейсы/часы работы. Цена, места и полный адресный маршрут остаются `unknown`. Ссылка [на официальную продажу](https://flyredwings.com/booking/) доступна как `purchase/entry`.

### Ограничения проверки

Авторизованные API-запросы, сравнение полной поездки на выбранную дату и предзаполненная покупка **NOT_RUN**. Navigation deep links сверены с документацией; фактическое открытие в приложении/отрисовка маршрута не тестировались. Табло и HTML проверены HTTP, не браузером. Источники расписаний не гарантируют точность/полноту будущих рейсов.

У Пулково `https://pulkovoairport.ru/transport/bus/` текстовый web-инструмент вернул 502, прямой HTTPS — `SSL: CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`; проверка TLS не отключалась. Корни `kazan.aero` и `vnukovo.ru` дали HTTP 200 без извлечённого видимого текста; содержание не подтверждено. `svx.aero` штатно перенаправил на `ar-svx.ru`, где текст доступен. Эти ограничения не доказывают отсутствие маршрутов/API; для результата хватило доступных первичных страниц, переходить к браузеру не потребовалось.

## Что остаётся получить для живого прототипа

1. Новый ключ Расписаний, его действующую квоту и допустимый объём объединения/ранжирования данных; выполнить `carrier/`, `search/`, `schedule/`, реальный пример пересадок и `copyright/`.
2. Для адресов — новый 2ГИС Geocoder/Routing доступ; проверить аэропорты, расписание на время поездки, отказ при недоступном транспорте и условия обработки без постоянного кэша.
3. Стабильный контракт prefilled search/purchase от Red Wings или уполномоченного продавца. До него честно показывать вход в продажу и повторяемые пользователем параметры.
4. Если продукт обещает цену/наличие — договорный read-only билетный поиск с составом тарифа, временем котировки, пассажирами и сроком предложения. Отдельно подтвердить инвентарь WZ и железнодорожных/автобусных плеч.

Исследование завершено как выбор коннекторов и спецификация прототипа. Подключённый живой поиск, доступные билеты и продажа не подтверждены.
