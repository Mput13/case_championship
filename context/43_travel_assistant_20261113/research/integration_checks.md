# Проверки интеграции Travel Assistant

Координатор, 13.11.2026. Это список приёмки и выявленных ограничений первой реализации, не независимый вердикт.

## Исследования

Аналоги подтверждают два сценария: подбор поездки с обязательным RW и неизменный уже выбранный рейс. География всей поездки может выходить за аэропорты RW. В готовом мультимодальном варианте необходимы датированные наземные участки и проверка переходов; навигационные рекомендации сами по себе этого не подтверждают.

Trip&Fly подтверждает потенциальный договорной билетный контур. Единый платёж и защита стыковки отсутствуют в нашем текущем продукте. Гипотезы влияния на продажи не являются результатом расчёта сети.

## Требования к первой демонстрации

- Изменение города, даты и номера выбранного рейса реально влияет на поиск; неподдержанная география обозначается.
- Во всех показанных вариантах есть подтверждение перевозчика Red Wings.
- Самара, Курумоч; Екатеринбург, Кольцово; вокзал и аэропорт — отдельные узлы.
- Отсутствующее время прилёта, стоимость и наземная длительность остаются неизвестными. Нельзя ранжировать по полной цене/времени без полного покрытия.
- Снимок, live-расписание, места и готовый билет различаются.
- Выбранный рейс не заменяется другим при продолжении поездки.
- Условия, введённые пользователем и не поддержанные системой, нельзя молча считать применёнными.
- Ошибка источника не превращается в отсутствие маршрутов или скрытое использование снимка.
- Модель не выдаёт произвольные рейсы, URL или команды как результат планировщика.
- Ключ отсутствует в JS/HTML, выдаче API, Git и логах; TLS проверяется только с явно настроенным контекстом для МАИ.

## Первичные замечания к интеграции

1. Первая реализация ядра умеет прямые рейсы RW плюс рекомендации дороги до/после аэропорта. Это ограниченный прототип; поиск городов без аэропорта и датированный наземный граф ещё не реализованы.
2. Поле «Пожелания» в UI обещает адрес/багаж/время выезда; начальный планировщик использует отдельные адресные поля, а свободный текст не применяет. Нужно реализовать обработку поддержанных условий либо убрать ввод, который молча игнорируется.
3. UI принимает 2000 символов пожеланий и 160 символов города, первая серверная валидация — 1000 и 100. Лимиты надо согласовать.
4. Перед показом проверить режим live без ключа: health не должен создавать видимость работающего расписания.
5. Дополнительный CA требуется только запросам МАИ; глобальное доверие и системные профили менять не нужно.

## Размещение

Node.js-сервер и отдельный CA подходят для выделенного контейнера/VPS. Sites работает на Cloudflare Workers; поддержка требуемого доверия к сертификату МАИ в этом окружении ещё не подтверждена. Нельзя считать статическую публикацию интерфейса полноценным работающим агентом. До выбора среды и проверки TLS, transport API и URL участников deployment остаётся NOT_RUN.
