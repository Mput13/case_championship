## 2. Агентский цикл (протокол работы Middle Man)

Каждый рабочий цикл состоит из 6 шагов:

1. **Консул → Постановка (1 параллельный прогон 4 моделей):**
   - Получает компактный бриф текущего состояния (≤1–2 экрана + пути к ключевым файлам).
   - Каждый член Консула отвечает по жёсткому шаблону: *(а) главные проблемы/риски объективности, (б) какие данные/проверки критически нужны, (в) конкретные задачи на следующую волну, (г) что НЕ делать (отсев лишнего)*.
2. **Оркестратор → Синтез и раздача ТЗ:**
   - Сводит 4 позиции Консула в единый `round_N_brief.md` (кворум: 3/4 или 2/3; при расколе 2–2 решение принимает Оркестратор с фиксацией обеих позиций).
   - Нарезает независимые задачи с **непересекающимися выходными файлами** (чтобы параллельные агенты не конфликтовали в shared checkout).
3. **Ресерчеры (`gpt-6.1-terra xhigh`) + Воркеры (`gpt-6.2-sol xhigh`) → Исполнение:**
   - Запускаются параллельными пачками через `delegate_task` (`mode: "async"`).
   - Не запускают своих субагентов, не делают Git-операций, сдают проверяемые файлы + краткий отчёт с источниками и явными пробелами `[UNAVAILABLE]` / `[NEEDS-RW-DATA]`.
4. **Оркестратор → Сборка и базовая валидация:**
   - Проверяет целостность CSV/JSON/ссылок и запускает скрипты воспроизводимости.
5. **Ревьюеры (`gemini-4-neon high` + `gpt-6.2-sol xhigh`) → Двойное ревью:**
   - Проверяют пакет одновременно по двум осям: (1) соблюдение исходных принципов (`AGENTS.md` / бриф RW), (2) точное выполнение задач Консула.
   - Размечают каждое замечание по уровню: `P0 / BLOCKER`, `P1 / IMPORTANT`, `P2 / NICE-TO-HAVE`, `EXTERNAL-BLOCKED`.
   - **Обработка замечаний:** `MINOR` оркестратор правит сам; при наличии `P0 / BLOCKER` запускается **ровно 1 целевой фикс-цикл** нужного воркера/ресерчера (повторное ревью — новым `delegate_task`, не `t3_thread_send`).
6. **Возврат в Консул → Решение по следующему шагу или Sign-off:**
   - Консул получает итоги волны + вердикт обоих Ревьюеров и принимает решение: запустить следующую волну с уточнениями ИЛИ закрыть Срез 1 (`SHIP`).

## 4. Definition of Done (DoD) — измеримые критерии завершения

### Срез 1 (к рабочей встрече с экспертом Red Wings, до получения внутренних данных RW)
Работа **завершена и передаётся пользователю**, когда выполнены все 7 пунктов:

1. **Скрининг (`Screening DoD`):** в `organizations_screening.csv` оценены **≥50 организаций** по 7 секторам (включая Ростех, Росатом, Газпром и их ключевые холдинги) по единым 6 критериям; у каждой явный статус (`Go / Conditional / No-Go`) и источник; все `No-Go` объяснены в `why_not_registry.md`.
2. **Бенчмарки и контракты (`Track B DoD`):** разобраны **≥8–10 кейсов** (минимум 4 РФ + 4 зарубежных, включая минимум 1 кейс провала/сворачивания и блок срочных/событийных ad-hoc перевозок), оформлена `rf_adaptation_matrix.md` (223-ФЗ, НДС 0%, флот/резерв/«Ковёр», ведомственные а/к, ТМС) и 4–5 готовых термшитов контрактов.
3. **Граф связей и событий (`Graph DoD`):** для всех `Go`-структур собраны площадки, ключевые цепочки поставщиков (внутренние и внешние), срочные проекты с датой спада и календарь **≥10–12 форумов 2026–2027** — без фильтра старой сети RW и без объединения московских аэропортов в `MOW`.
4. **Объём, бизнес-класс, Supply Gap и пулинг (`Demand DoD`):** на **топ-20–30 приоритетных парах/кластерах** посчитаны мобильные когорты (`Min / Base / Max`) и доля бизнес-класса, проверено текущее расписание авиа и ЖД (`GAP-1..4` или `NO-GAP`), показаны зоны **мультикорпоративного пулинга** и оценка естественных узлов (вкл. Екатеринбург). Закрыты открытые проверки Issue #5 и учтены ограничения Issue #6.
5. **Флот и двусторонняя экономика (`Fleet & Econ DoD`):** маршруты ранжированы по дальности и ёмкости → оценён потребный парк по типам ВС и компоновкам; по **топ-5–8 кластерам и 2–3 пилотам** (вкл. Уфа ↔ НУР) посчитаны бюджет клиента (`TCT`) и сценарный порог безубыточности RW (с явной маркировкой `[NEEDS-RW-DATA]`).
6. **Чистое двойное ревью (`Quality Gate DoD`):** оба ревьюера (`gemini-4-neon high` и `gpt-6.2-sol xhigh`) выдали `PASS` с **0 открытыми `P0 / BLOCKER`**: нет выдуманных фактов/URL, нет перевода рублей закупки в кресла, нет смешения единиц, нет скрытых нулей вместо неизвестных, формулы воспроизводимы.
7. **Готовый комплект для эксперта (`Delivery DoD`):** готовы и проверены 3 артефакта:
   - интерактивное HTML-досье `redwings_corporate_dossier.html` (непрерывный документ с закреплённым оглавлением, картой/фильтрами и живой калибровкой параметров + экспорт правок JSON);
   - рабочая книга Excel `redwings_corporate_model.xlsx` с живыми формулами по листам;
   - одностраничный `briefing_memo.md` (4 вывода, 2 спорные гипотезы, 5 вопросов к Red Wings).

### Срез 2 (после встречи и получения данных от Red Wings)
- **Ровно 1 короткий цикл калибровки** (без повторного скрининга): подставить диапазоны затрат RW, планы по бизнес-классу и свободные окна флота в модель → обновить HTML-досье, XLSX и коммерческие карточки → 1 прогон Ревьюеров → выдача.

## 5. Пять жёстких ограничителей бюджета токенов (Anti-Loop Guardrails)

Чтобы Консул не уходил в бесконечную доработку и не сжигал бюджет:

1. **Жёсткий потолок раундов Консула:** **максимум 3 макро-раунда** на весь Срез 1 (`Раунд 0` → `Раунд 1` → `Раунд 2`), плюс при необходимости **1 короткий бинарный Sign-off** только по закрытию `P0`-блокеров. Открывать новые ветки исследования после Раунда 2 **запрещено**.
2. **Лимит исправлений по ревью:** **максимум 1 фикс-проход** воркеров/ресерчеров на волну и только для `P0 / BLOCKER`. Все `MINOR`-замечания оркестратор исправляет сам.
3. **Жёсткий фильтр приоритетов (`P0 / P1 / P2 / EXTERNAL-BLOCKED`):**
   - `P0 / BLOCKER` — чиним обязательно.
   - `P1 / IMPORTANT` — берём только в пределах текущего раунда и лимита пачек.
   - `P2 / NICE-TO-HAVE` — **не запускаем**, складываем в `backlog_after_rw.md`.
   - `EXTERNAL-BLOCKED` (внутренние данные RW или недоступная карточка ЕИС после 1 верифицированной попытки) — **не перезапускаем поиск**; маркируем `[NEEDS-RW-DATA]` / `[UNAVAILABLE]` и переносим в вопросы эксперту.
4. **Кворум вместо вечного консенсуса:** решение Консула принимается большинством (**3/4**, или **2/3** при уходе `claude-opus-5-5` в лимит); при расколе 2–2 решает Оркестратор и фиксирует расхождение в журнале (чтобы эксперт сам рассудил на встрече).
5. **Правило компактного контекста:** Консул и Ревьюеры получают от Оркестратора структурированные сводки и пути к таблицам, а не сырые дампы; каждый агент работает только в своей зоне записи, без дублирования поисков.
