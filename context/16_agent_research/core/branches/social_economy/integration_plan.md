# Интеграция социальных и экономических данных

Все пути относительны `core/branches/social_economy/`. Ведущий может включить эту папку в общий манифест, ссылаясь на `dataset_manifest.json` и `coverage.csv`. Публикация всех статистических ячеек проверена структурно; независимая сверка всех официальных исходников не выполнена. Рейтинга городов или веса эти скрипты не устанавливают.

Для региональных признаков использовать таблицу `regional_selected_latest.csv` с обязательными `year`, `indicator_unit`, `source`, `value_status`, `value_missing_reason`, `object_level` и вариантом включения автономного округа. При необходимости единого периода выбрать конкретный год из `regional_selected_panel.csv.gz`, сохранив пропуски. Окончательный общий год и дефлятор — отдельное решение оценщика.

Для локального контекста начать с `example_join_municipal_2024.csv` и действующего исходного ОКТМО 2024. Муниципалитет не равен городу или зоне тяготения. `oktmo_stable` полезен для исследования истории, но перед соединением лет проверить `oktmo_history`, `oktmo_year_from/to` и фактическое изменение границ. Неоднозначные коды не агрегировать автоматически. Перед массовым соединением с аэропортами нужна отдельная версия airport→municipality/settlement→region; городской суффикс или имя города недостаточны.

`region_crosswalk.csv` имеет 85 строк, явные восемь соответствий написания и правило исключения автономных округов из материнского региона. `canonical_area_id` — внутренний ключ пространства `rosstat_region`, а не ISO и не муниципальный ключ. Сырой ISO census не применять как канонический: диагностические исключения сохранены, остальные геокоды тоже ещё не проверены. Для координат следует предпочесть верифицированный аэропортовый справочник и отдельную проверку географии.

Архивный XLSX 2025 и его 19 716 разобранных строк пока держать как дополнительный срез с полем `UNAFFILIATED_ARCHIVE_MIRROR_NOT_LIVE_VERIFIED`. До получения первичного файла он не должен незаметно вытеснить сверенные источники. ТЕРСОН-МО не преобразовывать в ОКТМО удалением цифр.

Воспроизведение из корня репозитория, без установки зависимостей:

```sh
python3 context/16_agent_research/core/branches/social_economy/collectors/collect_social.py
python3 context/16_agent_research/core/branches/social_economy/collectors/normalize_social.py
python3 context/16_agent_research/core/branches/social_economy/collectors/normalize_bdmo.py
python3 context/16_agent_research/core/branches/social_economy/collectors/probe_unavailable.py
python3 context/16_agent_research/core/branches/social_economy/collectors/finalize_social.py
```

Нормализация архивного XLSX использует уже имеющийся `openpyxl`; остальное — стандартная библиотека Python. Все raw и скрипты компактны, тяжёлой среды нет. При повторном получении `--refresh` обновляет снимок; для сохранения старой доказательной версии сначала скопировать манифест и raw под новой версией. Обычный запуск сохраняет ранее полученные байты.
