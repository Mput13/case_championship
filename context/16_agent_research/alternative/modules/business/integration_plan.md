# Объединение корпоративного модуля

Файлы разрешаются относительно этой папки. Для замороженного воспроизведения запустить из корня репозитория:

```bash
python3 context/16_agent_research/alternative/modules/business/collectors/normalize_business.py
```

Новая загрузка HTML не перезаписывает снимок:

```bash
python3 context/16_agent_research/alternative/modules/business/collectors/fetch_business.py --download
```

Она создаёт отдельную папку raw/refresh_<UTC>. Проверка нового снимка и обновление ручного соответствия адресов выполняются явно. Для исторического источника точный запрос native web search: `site.rosneft.ru/press/news/item/185797/ "Вахты в Игарку"`; полноценный источник HTML остаётся ACCESS_FAILED. Утверждение из поискового индекса не получает статус прочитанного первичного документа.

## Таблицы и ключи

- `sibur_sites.csv`: уникальный site_id внутри group_id и snapshot_id. source_modal_id — исходный ключ, две пустые записи имеют отдельный site_id с номером карточки и не объединяются с координатами. `group_site_membership.csv` — только принадлежность к опубликованному перечню группы.
- `sibur_map_markers.csv`: сырой разбор массива точек; пустой marker ID сохраняется вместе с его повторяемостью. Не соединять такие строки как один ключ.
- `sibur_area_map.csv`: прозрачное ручное соответствие адреса стране/ISO-региону и локальной метке. Это DERIVED-метаданные; они не являются полной area_version. До присоединения к общему справочнику нужны canonical area_id, версия границ и явное правило аэропортового доступа.
- `gazprom_shift_observations.csv`: ключ organisation_id + indicator_id + period + snapshot_id. Не соединять эти групповые показатели со всеми площадками или городами через копирование одного значения.
- `historical_vankor_routes.csv`: пять направленных исторических city→city statements. Поля airport_hint — подсказки для ручной проверки, не коды аэропортов из источника; Москва обозначена MOW. weekly_flights и annual_passengers пусты с причиной, текущий service status UNKNOWN.
- `historical_vankor_aggregate.csv`: один отдельный аэропортовый месячный агрегат работников 2017 года. Это не OD и не строка каждого направления.

## Проверки перед join

Проверить уникальность canonical airport/area справочника и вывести все unmatched; не присваивать ближайший аэропорт по одному региону. Сохранять 11 зарубежных записей как outside-Russia, а не терять их без отчёта. Амурский проект и Полимеры в Башкортостане должны иметь разные регионы. Районы, посёлки, месторождения, город и авиационная зона — разные уровни.

Пример допустимого следующего преобразования: для каждой российской площадки определить несколько наблюдаемых путей доступа к аэропортам по дорогам/расписаниям; затем отдельно оценить командировки конкретной категории. Расстояние по прямой само по себе не устанавливает такой путь. Полный граф пар площадок и умножение headcount на частоту в этом пакете отсутствуют.

## Проверка полезности

В историческом тесте использовать только сведения, опубликованные до даты решения. Дата публикации текущей страницы СИБУРа и отчёта Газпрома неизвестна: текущие снимки нельзя вставлять в старый backtest как заранее известные. Историческая Роснефть имеет дату 2017-02-27, но требует независимой проверки исходника/архива.

До калибровки текущего OD использовать признаки только для поиска и аудита причинной гипотезы. Затем сравнить модель население + доходы + расстояние + базовая авиационная доступность с той же моделью и корпоративным признаком на отложенных исторических линиях. Отрицательный контроль: пары городов со схожим масштабом предприятий, но без общего корпоративного процесса. Дополнительная ablation: удалить Москву и соседние с аэропортом площадки, чтобы проверить, не отражает ли признак только общий размер города.
