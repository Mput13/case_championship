# Передача результатов критика

Писать в общие таблицы и чужие worktree из этой роли нельзя. Координатор интегрирует файлы `critic/` после проверки путей и SHA. Международный ребёнок пишет в `critic/international/`: это осознанное разрешение коллизии брифа с ограничением роли. После Sol-проверки координатор может перенести пакет в общий `international/`.

Приоритеты: извлечение Telegram body до счётчиков ограничений; разделение missing_reason в rail/gap; наличие базы vs неизвестный конкурент; актуальный этап 16 вместо исторической Б0; сверка чистого дохода, перетока и платежных порогов.

Входы соседей читаются без изменения. Для каждого приёма — путь, снимок manifest/status/progress, хеш и время; фактическая проверка источника/семантики отдельно от схемы. Файлы, появившиеся во время чтения, не считать финальными; фиксировать отдельный snapshot для следующих проверок.

Обычные агрегаты и прокси можно включать в feature_observation с ограничением; нельзя помещать их в od_observation. Предложения протокола и gates — в методологию, не в эмпирические данные. Finding с ALREADY_FIXED нужен для истории ревью, но не блокирует заново. Неизвестные факты, блокирующие запуск, не запрещают условную учебную презентацию, если ограничение понятно.
