# Публикация checkpoint

Разрешение пользователя на push собственной исследовательской ветки получено 9 ноября 2026; прежний запрет push отменён. Merge/rebase чужих веток, force push и изменение main не разрешены и не выполнялись. Публикация не повышает acceptance.

В Git входят собственные отчёты/код, фактические производные таблицы, manifests и SHA256. Первичные HTML/PDF, их полные текстовые извлечения/скан и копии чужих pinned exports остаются локально под `.gitignore`. Для части веб-материалов право полной перепубликации не установлено; свободный доступ не принят за лицензию. Объём и хеш каждого исключённого файла — `local_raw_manifest.json`. Raw не удаляется и не меняется из-за push.

MIT OCW указан с автором, названием и ссылкой; полные PDF/извлечение в checkpoint не включены. OurAirports опубликован поставщиком как Public Domain, но его исходный архив здесь тоже не дублируется. NOAA и Tochno сопровождаются собственными upstream manifests и источниками; это не согласие считать архивы достоверным спросом. Доступность документа отдельно от лицензии и истинности.

Повторное получение документов: `collectors/collect_primary_sources.py --only C01` и аналогично C02–C10; C08–C10 — вторичные публикации, а не оригинальные ряды аэропортов. Сетевой запуск получает новую версию mutable bytes, старые хеши нельзя молча заменить. Фактические времена/команды первоначального получения сохранены в dataset manifest; после санитарной правки действует collector v2 с whitelist response headers. `collectors/normalize_tax_sources.py` воспроизводит декодирование двух полученных налоговых HTML. `collectors/check_front_source_context.py` сверяет сохранённые контексты C08–C10.

Pinned git exports восстанавливаются через `git show <input_sha>:<repo_path>` по manifests; основные сверки stage15–17 и `collectors/audit_published_packages.py` сами извлекают pinned blobs. Stage18: `python3 collectors/restore_stage18_inputs.py`, затем `python3 stage18_audit/reproduce.py`. Новый front: `python3 front_demand_audit/capture_inputs.py`, затем `python3 front_demand_audit/reproduce.py`; внешний Tochno ZIP требуется по указанному хешу. Это не запускает код авторов. Первичные странички stage18 требуют отдельного сбора по `primary_manifest.json`, не нужны для арифметического replay.

Срезы core/hypotheses сохранены внутри evidence; для raw core/alternative проверяющие скрипты используют внешние content-hashed архивы по указанным manifests. Они должны переноситься владельцами соответствующих ролей. Недоступный локальный архив означает `NOT_RUN` при новом replay, а не опровержение старого результата. Полные условия повторного сбора NOAA находятся в сохранённом `weather_audit/inputs/collectors/weather.py` и receipts, координаты и определения — в исходных registry.

Секреты HTTP не являются исследовательским входом: Cookie/Set-Cookie/Authorization не сохраняются в manifests; whitelist и повторная проверка задокументированы. При импорте чужих JSON manifests заголовки тоже фильтруются: `sha256`/`bytes` относятся к исходному Git blob, `stored_sha256`/`stored_bytes` — к фактически сохранённой очищенной копии, `storage_transform` объясняет различие. Исходные HTML и их хеши не изменяются. В checkpoint не включаются формы авторизации, личные контакты, профили, токены или provider logs. Проверка выполняется перед staged commit; её область не означает аудит всего upstream репозитория.
