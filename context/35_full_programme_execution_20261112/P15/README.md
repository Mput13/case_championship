## Воспроизведение

Из корня репозитория:

```sh
python3 context/35_full_programme_execution_20261112/P15/replay.py
python3 context/35_full_programme_execution_20261112/P15/verify.py
python3 context/35_full_programme_execution_20261112/P15/prepare_qa.py
```

`replay.py` читает только выбранные сохранённые снимки, проверяет manifests/hashes и собирает HTML/данные. Нового сбора, модели спроса, распределения кресел и денежных расчётов в нём нет. В `inputs/` находятся только использованные JSON/CSV и manifests, без чужих архивов/fixtures, raw HTML, зависимостей и runtime. `claim_links.csv` содержит 10745 связей с IDs, порядком строк, исходными полями и каноническими SHA256 записей; исходные source_row_hashes сохранены отдельно в авторских полях.

При принятом root envelope адаптер читает `projection_contract.json` и каждый `audit_receipt` через `git show` того же точного artifact commit. Из receipt копируются input_manifest/full и ссылки audit/replay; повторять эти метаданные в evaluation не требуется. Проверяются канонический projection SHA256 и соответствие full-result ссылок. Исходные поля `result` не изменяются; overview числа не используются.

Точный Git blob проходит структурную проверку `validate_result.cjs`. Контекст, значения, null, status и evaluation links сохраняются; producer-ready годовые/24месячные итоги не пересчитываются и не округляются в данных. Видимые числа форматируются отдельно. `operating_result=null` и полное финансирование UNKNOWN остаются неизвестными. `known_operating_subtotal` — отдельный известный операционный подытог, не полная прибыль.
