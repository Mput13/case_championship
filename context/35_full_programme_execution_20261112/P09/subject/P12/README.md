## Сборка

Из корня репозитория, Python 3 и стандартная библиотека:

```sh
python3 context/35_full_programme_execution_20261112/P12/build.py
python3 context/35_full_programme_execution_20261112/P12/verify.py
python3 context/35_full_programme_execution_20261112/P12/prepare_qa.py
```

Сборщик читает именно `git show SHA:path`. Все 48 использованных Git blobs и их хэши перечислены в `input_manifest.json`. Копии прочитанных файлов — в `inputs/`; большой исходный HTML панели закреплён хэшем без дублирования. `source_version_links.json` связывает SHA, путь, локальную копию и GitHub blob. `verify.py` проверяет используемые файлы, которые покрыты upstream manifest, и собственные снимки. Проверка хэшей не подтверждает применимость рынка или полноту экономики.

HTML не требует сервера, npm, сетевого D3 или Google Fonts. Исходные системные fallback шрифтов используются для автономности. Записи и методы доступны офлайн внутри интерфейса, первичные внешние страницы открываются по сохранённым URL при доступной сети. Их живое содержимое повторно не проверялось и не объявляется текущим.

## Подключение результатов P15

`ui_contract.json` определяет envelope, названия полей и границы. Есть два работающих входа: локальный JSON через раскрытие внизу UI и `RW.load(package)`; закреплённая сборка:

```sh
python3 context/35_full_programme_execution_20261112/P12/build.py \
  --results-commit EXACT_40_HEX_SHA \
  --results-path PATH_TO_ACCEPTED_PACKAGE_IN_GIT
```

Пакет содержит `dataset_kind=RED_WINGS`, `synthetic=false`, `coordinator_acceptance=ACCEPTED_FOR_UI`, точные commit/manifest и `evaluations`. Каждый evaluation содержит подписи, source_refs, assumption_ids и неизменённый P06 compare output в `result`. Проверяются 24 месяца и совместимость KEEP. Импорт выполняется с восстановлением прежнего состояния при ошибке. Проверка структуры и метки приёмки не является проверкой подлинности приёмки координатора.

Месячные значения, годовые агрегаты, сеть, ротации, финансирование и сравнение сценариев отображаются из producer outputs. JavaScript не считает спрос, размещение, прибыль или новое расписание. `evaluation.resource_monthly` — дополнительный отображаемый экспорт принятого календаря, без конструирования физических бортов. Сценарные сравнения сохраняют основную программу; общая группа сравнения может быть явно закреплена `comparison_group_id`. Для №2 дополнительно нужен `release_gates.F07=ACCEPTED` и стратегия по тому же evaluation_id.

Новый город добавляется данными в `ui_candidate/data/city_extensions.json` с новой версией, source_refs, assumption_ids, координатами и известными либо null полями покрытия, затем пересборкой. Переопределить существующий город таким способом нельзя. Это расширение исследования; общий market input и итоговая программа от этого не меняются.

## Проверка и границы

`qa/interaction-desktop.json` и `qa/interaction-narrow.json` содержат по 28 проверок реального DOM в нативном html_preview (1440 и 390 px). Проверены якоря, выбор города, реальные фильтры, источники, допущения, фокус, отсутствие выдуманного сценария, отдельный период источника, слои, маршрут, свободный просмотр/возврат и отказ синтетическому импорту. После уточнения атомарного импорта и сохранения версии выполнены восемь затронутых проверок в `qa/targeted-errors.json`. Успешный импорт реального конечного пакета пока NOT_RUN.

Реальные снимки desktop, narrow, source-narrow и projector-network сохранены в `qa/`. Projector означает проверку компоновки на ширине 1280 px, не физическое испытание проектора. В широких таблицах и карте на узком экране предусмотрена внутренняя прокрутка. Последующая правка обработки невалидного импорта и пустое расширение городов не меняют проверенную компоновку; финальный inline показ использует актуальную сборку.

Первый selftest после перестановки полей источника дал ложный FAIL: он запрещал текст `source_locator`, хотя раскрываемая исходная запись теперь правомерно сохраняет это поле. Проверка заменена смысловой — открыто окно и доступна строка источника. Исходный failed log сохранён; затем оба прохода дали PASS. Это исправление проверки, не численной модели.

`presentation_route.json`, `presentation_preset.json`, `presentation_script.txt` и `presentation_rehearsal.json` задают проход 0–120 секунд в том же UI. Навигация реализована. Final results, одно реальное переключение рассчитанного сценария и полноценная репетиция: **NOT_RUN**. P15 закрепляет реальные примеры и пакет; P16 независимо проверяет интерфейс и репетицию. Автор P12 не является независимым проверяющим P16.
