# P06 — общее расчётное ядро

Ранняя исполняемая версия интерфейса. Все числа в `examples/demo_bundle.json` — искусственная проверка механизмов, не параметры или прогноз Red Wings. Полная адресная проверка P00R в этой версии ещё не выполнена.

Из корня P06:

```sh
python3 -m engine compare examples/demo_bundle.json --out examples/demo_result.json --tables examples/tables
```

Python standard library; установка зависимостей не нужна. `evaluate` получает один bundle, `compare` — объект с `project` и `keep`, `scenario` — объект с `bundles` и optional `parents`. JSON null обозначает UNKNOWN. При нарушении контракта CLI сохраняет INVALID и завершается с кодом 2.

`producer_contract.json` содержит обязательные поля, владельцев и пример каждой непустой таблицы. Канонический JSON hash `input_manifest` закреплён в context. Сам manifest должен ссылаться на exact commit и SHA256 producer inputs. Hash не означает приёмку этих inputs координатором.

P03 передаёт датированные физические смежные рейсы, отдельные борта, ввод, исходную позицию, окна экипажа, ТО, резерв и назначения. Календарь месяцев и число блок-часов этого не заменяют. Перегон — отдельное физическое плечо. Одинаковый доступный/обязательный парк передаётся P и KEEP; неиспользованные борта сохраняются в выходе и в платёжных обязательствах.

P05 передаёт единые взаимно исключённые demand pools по месяцу/сегменту и продуктовые альтернативы: сопоставимую gross цену, длительность, частоту, доступность, один net тариф поездки и ordered dated legs. Потенциальный спрос отличается от наблюдаемых воздушных OD. Опубликованный endpoint pair P02 не является физическим инвентарём. Несколько программ в одной оценке используют общий рынок и места.

P04 передаёт события начисления и оплаты с владельцем и единицей драйвера; предзапусковые платежи включаются начиная с cash_start. Переданный справочный тариф не применяется к 2027–2028 без отдельного assumption_id переноса. UNKNOWN цены/оплаты не заменяется нулём. `cost_coverage` требует явного состояния variable_cost/base/aircraft_use/reserve/startup/exit/support. `cash_coverage` отдельно задаёт operating/investing/tax/financing. Сведения о капитальных вложениях, налогах и финансировании не входят в операционный результат. Депозиты и оплаты после горизонта сохраняются.

Общее ядро считает ожидаемые дробные поездки условной logit-функцией и пропорционально распределяет дефицитные кресла с повторным выбором остатка. Это объявленная эвристика распределения, не revenue-management оптимум. Коэффициенты требуют источника/сценарного ID. Тестовая нулевая эластичность не является эмпирической оценкой.

В этой версии есть численная демонстрация P−KEEP, а не вывод о рыночной выгоде программы. Не установлены диспетчерская готовность, полная компания/финансирование, рейтинг №2 и глобальный оптимум. Существующие авторские результаты сохранены как отдельные входы: их недельные деньги не суммируются в новом расчёте.
