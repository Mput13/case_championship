# Ханты-Мансийск, Ленина 109 → Миасс

Проверка: **13.11.2026, 16:14–16:23 МСК** (UTC 13:14–13:23). Все транспортные часы ниже — местные, **UTC+05:00**. Коридоры относятся к окну **01.12.2026–15.01.2027**, смысл которого ещё не установлен. **11 декабря — дата исследовательской проверки, не выбор пользователя.**

Первый вопрос в чате: «Это окно возможного выезда или даты всей поездки с возвращением?» Затем нужны пассажиры/багаж, крайний срок прибытия, точный адрес в Миассе и допустимость дальнего такси, ночного переезда и ночёвки. Не называть этот диапазон отпуском и не назначать даты туда/обратно.

## Почему обязательный RW может ухудшить поездку

На **пятницу 11.12** прямой UT301 публикуется с прибытием в Кольцово **10:45**, а WZ1018 из Сургута — **18:20**: разница прибытия в общий узел **7 ч 35 мин**. Это **не** рассчитанная разница времени от двери до двери. RW-коридор дополнительно требует пяти с половиной часов автобуса и ожидания в другом аэропорту. После SVX наземное продолжение у обоих вариантов одинаковое, поэтому крюк нельзя скрыть заменой конечного узла.

Другой базовый путь ведёт прямо в Челябинск. Один оператор публикует ориентиры **CEK↔Миасс около 115 км/1 ч 40 мин**, **SVX↔Миасс около 250 км/3 ч 40 мин**. Это оценки оператора, преимущественно на страницах обратного направления; на подачу после конкретного рейса они не дают договорной гарантии. Более короткий дорожный участок — основание проверить CEK первым, а не объявлять весь путь самым быстрым или дешёвым. [Баландино](https://businesstransfer.ru/transfer/miass-balandino/), [Кольцово](https://businesstransfer.ru/transfer/miass-koltsovo/).

Перелёт SVX→CEK не добавлен: оба аэропорта дают самостоятельный наземный выход к Миассу.

## Интеграция и границы

`case_routes.json` содержит **nodes, legs, corridors**. `corridors[].legs` — готовые объекты по форме API контракта; `leg_ids` ссылаются на общий реестр. `case_sources.json` содержит URL, время GET, SHA-256 и извлечённые факты. Для локального snapshot время исходной загрузки **null**, отдельно указано время чтения; оно не выдано за свежий сетевой ответ. Прямая повторная загрузка страницы вокзала Миасс вернула **503**, сохранён индексированный первичный текст и граница проверки.

У паттернов часы хранятся в `schedule_pattern`; `departure`/`arrival` остаются null до выбора даты. Списки `dates_in_requested_window` получены пересечением дней недели/периода с окном, **не** проверкой продаж. У RW11.12 поле прибытия имеет отдельный `field_evidence: published_pattern`. Такси `indicative`, доступ от дома и непроверенный переход `unknown`.

Все `price`, `seats_available`, `total_price`, `total_duration_minutes` — **null**. Опубликованные прайсы не стали ценой пользовательской поездки. Не складывать только известные длительности в «общее время», не дорисовывать даты/стыковки моделью. Сначала уточнить смысл периода, затем выбирать перспективные дни по календарям и проверять слабые участки.

Секреты не искались; платные API, покупка и внутренние билетные endpoints не вызывались; браузер и дочерние агенты не использовались. Keyless API с известным `key_required` повторно не вызывались. Код и Git не менялись.
