# Размещение Travel Assistant

Адрес демонстрации: https://redwings.altair.ad/agent/. Сервер: `45.150.36.187`. Размещение и перенос имеющихся ключей явно разрешены пользователем 13.11.2026. SSH-пароль и ключи в этот пакет не включаются.

## Сервис и доступ

Приложение находится в `/opt/redwings-agent`, Node.js 22.23.5 — `/opt/redwings-node`. Бинарный архив получен с `nodejs.org`, SHA-256 проверен по опубликованному манифесту. `npm ci --ignore-scripts` установил 88 пакетов по lock-файлу. Сервис работает под отдельным системным пользователем `redwings-agent`; внутренние TCP-порты доступны только с loopback.

`redwings-agent.service` слушает 3088 и сохраняет прежние сессии. `redwings-agent-v2.service` слушает 3089 и сохраняет прежние сессии. Актуальная версия `redwings-agent-v3.service` слушает 3091; новый браузер обращается через `/agent/api-v3/`. Это позволило обновить лимиты без остановки прежнего процесса. Сессии процессов не общие: обновление страницы начинает работу с новой версией.

Лимит ответа — 4096 токенов, ожидание одного модельного вызова — 120 секунд, хода — 180 секунд, HTTP/proxy — 240 секунд. Число модельных вызовов на ход осталось не более трёх, процесса — не более 1000. Это технические ограничения, не подтверждённая стоимость МАИ. Неопределённый платный POST не повторяется автоматически; неизвестный usage останавливает последующие вызовы процесса.

Ключи Яндекс Расписаний и МАИ находятся в `/etc/redwings-agent/{yandex,mai}.key`, права 0640, группа `redwings-agent`. Они не входят в веб-каталог, браузерный код, запросы браузера или Git. Для МАИ применяется отдельный доверенный российский CA только к этому хосту; TLS-проверка не отключена.

В `redwings-agent-demo-expiry.timer` установлено абсолютное время `2026-11-13 19:51:04 Europe/Moscow`: сервис остановит все три версии и удалит серверные копии двух API-ключей. Время не продлевается при обновлении версии. Исходный код и зависимости автоматически не удаляются.

## Дашборд

Корень сайта — `/var/www/redwings/current`, на момент проверки это release `c0187ecc1c3b7956f2f2898e29d6c088520d3fc4`. Файлы `index.html` и `redwings_panel.html` не менялись: SHA-256 до и после совпали. Nginx вставляет только ссылку «Агент» через `sub_filter` в ответы `/`, `/index.html` и `/redwings_panel.html`. При удалении добавленного `nav` остальные байты HTML-ответа совпадают. Остальные страницы и файлы не модифицировались.

Изменения nginx вынесены в `/etc/nginx/snippets/redwings-agent-{routes,button}.conf`; в существующий server добавлен один include. Перед graceful reload выполнен `nginx -t`. Исходная конфигурация и хеши дашборда сохранены в `/var/backups/redwings-agent-20261113/`.

Для ручного прекращения демонстрации: `systemctl start redwings-agent-demo-expiry.service`. Чтобы убрать и кнопку/маршруты, удалить только строку include `redwings-agent-routes.conf` из текущей конфигурации, проверить `nginx -t` и выполнить `systemctl reload nginx`. Не восстанавливать целиком старую конфигурацию, если после размещения появились чужие изменения.

## Демонстрационные режимы

Обычный пример сначала создаёт сессию из проверенного снимка, затем получает настоящий ответ Pi/DeepSeek. Даты и источники снимка остаются видимыми. В форме выполняется реальный транспортный поиск; при отсутствии пожеланий интерфейс затем отдельно запрашивает разбор модели в той же сессии, а пожелания проходят через Pi до поиска. После ответа можно продолжать чат.

«Офлайн-демо» открывает четыре проверенных снимка из предварительно загруженного `demo-snapshots.json`. Модель и транспортные API не вызываются, новый поиск и ввод сообщения выключены. После включения агента первый вопрос создаёт серверную сессию по выбранному снимку. Для работы при потере сети страница и файл должны успеть загрузиться; холодный запуск без сети и PWA не реализованы.

## Проверки

156 offline-тестов прошли после изменения лимита, включая принятие завершённого ответа с расходом 2200 выходных токенов, прежний запрет повторов, неизвестный usage и alias `/api-v2/`. Генератор офлайн-пакета проверил все четыре маршрута по схеме, UTC и буферам.

На опубликованном HTTPS-адресе проверены главная страница, CSS/JS, реальные подсказки мест, датированный выбор WZ 1034 и форма. Реальный поиск Самара → Нижний Тагил занял 8,93 секунды и вернул только WZ; цепочки остались `partial` из-за неподтверждённых наземных переходов, что явно показано. Этот результат не доказывает полноту поиска.

Первый длинный разбор при прежнем лимите 1200 закончился по лимиту; usage зафиксирован, автоматического повтора не было. После разрешённого повышения новый онлайн-пример получил настоящий ответ за 9,82 секунды, один модельный вызов, 6890 входных + 609 выходных токенов, usage `recorded`. Агент выбрал электричку №7067 с расчётным запасом 54 минуты и сохранил оговорки об автобусе. Денежная стоимость не подтверждалась.

Офлайн-режим проверен с принудительным отказом всех последующих `fetch` в отдельной браузерной вкладке: маршрут открылся, сетевых запросов 0, карточки есть. На CSS-экране 390×844 переполнения нет; поля формы 16 px, высота 48 px, кнопка построения 48 px. Проверена кнопка с дашборда. Проверка физической клавиатуры iOS/Android и нагрузочная приёмка большого зала — NOT_RUN.

Переход из офлайн-примера обратно в чат также проверен: по вопросу о выбранном рейсе автоматически создана сессия именно `feeder-flight`, затем получен настоящий ответ о WZ 1033. Один модельный вызов, 6534 входных + 122 выходных токена, usage `recorded`, 21,35 секунды. Снимок не пересказывался пользователем заново.

По отзыву пользователя добавлена видимая обработка готового примера: немедленно раскрывается область чата с выбранным маршрутом, индикатором и реальным прошедшим временем. Загрузка данных и разбор модели — разные статусы; фиктивные проценты и этапы поиска не показываются. После завершения или ошибки индикатор и таймер удаляются. Мобильный снимок: [agent-processing-mobile.png](screenshots/agent-processing-mobile.png).

Следующая правка по прямому отзыву: из основного результата удалены списки общих предупреждений, повторные пояснения о снимке/источниках, технические статусы каждого участка и сообщение об отсутствии подключённой корзины. Карточки показывают перевозки, время, расчётный запас и ссылки. Источники остаются свёрнутыми, сценарный режим отмечен; неизвестные времена и цены не заменяются числами. При открытии сценария или формы показывается краткая рекомендация агента, обсуждение продолжается в чате. Данные и проверки маршрутов на сервере сохранены.

Эта правка выложена атомарной заменой только `public-chat/app.js`, без перезапуска Node.js. Хеши файлов дашборда до и после совпали. На 390×844 проверен именно пример Тула → Москва из отзыва: два варианта, времена и ссылки на месте; `.plan-warnings`, технические статусы и общие предупреждения о разумности отсутствуют. Живой вопрос по результату получил ответ агента без ошибки. Снимок новой версии после перезапуска T3 получить не удалось: native browser сообщает отсутствие screenshot frames даже после `preview_open(..., open:true)`. Ошибка и DOM-проверка сохранены в [quiet_ui.json](receipts/quiet_ui.json); недоступный снимок не засчитан как визуальная приёмка.

Структурированные результаты: [deployment_public.json](receipts/deployment_public.json), [deployed_files.sha256](receipts/deployed_files.sha256). Исторические receipts с другими авиакомпаниями относятся к прежним версиям; текущая выдача допускает только авиацию Red Wings и наземные альтернативы.


## Обязательный перелёт Red Wings

После отзыва о Тула → Москва публичный результат требует сегмент WZ в каждом варианте. Фильтр применяется до передачи результатов поиска в чат, источник данных агента и браузер. Чисто наземный baseline остаётся внутри общего поискового ядра для ранжирования разумности; он не подменяет поездку с RW. Если WZ-варианта нет, предлагаются другие даты или аэропорт, а не список поездов.

Тула → Москва исключён из каталога и статического офлайн-пакета. На его месте — Кольцово → Курумоч, WZ 1033 8 декабря, 22:45 UTC+5 → 23:30 UTC+4, 105 минут. Датированное авиаплечо взято из уже проверенного feeder-flight; новых рейсов, времени и наземных участков не придумано. Остальные типы: подвоз к рейсу, продолжение после прилёта и отдельный сценарий Омск → Ольхон 2028. Каждый содержит WZ; будущий рейс остаётся сценарием.

157 offline-тестов прошли, включая запрет чисто наземного результата и смешанного авиаплана.
