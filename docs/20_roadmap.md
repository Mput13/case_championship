### 2.3 Правила хранения данных
- Сырые выгрузки — `data/raw/` с датой получения в имени файла; обработанные — `data/clean/`; оценки и синтетика — `data/synthetic/` с описанием метода рядом.
- У каждой строки колонка `source` (ссылка или «допущение: …» / «синтетика: метод …») и `status` (OBSERVED / SCENARIO / UNKNOWN — как у коллег в `context/07_verification/terra_data/data_model.md`).
- Пропуск остаётся пустым с причиной. В рейтинге пропуск обрабатываем по заранее записанному правилу и проверяем это правило в чувствительности.
- Ключи API — только в `.env`, файл в `.gitignore`.

## 6. Контрольные точки: когда этап считается готовым
1. **Лонглист:** 12–20 городов; у каждого значения есть источник или правило пропуска; топ-3 и частота попадания в топ-3 при изменении весов.
2. **Спрос:** у каждой пары сети есть четыре оценки или пометка, каких нет и почему; калибровка на 15+ известных потоках с ошибкой, записанной в README.
3. **Гипотезы:** одинаковый парк для обеих; пассажиры, выручка, доля в п.п. в двух мерах и двух сценариях; число самолётов по кварталам.
4. **Сдача:** все листы Excel заполнены; карта; паспорт; расчёт повторяется командой из README на чистой копии репозитория.
